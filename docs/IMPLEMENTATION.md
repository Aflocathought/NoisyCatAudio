## 1. 实现原则与依赖基线

### 1.1 以可独立测试的 DSP 为中心

自有 DSP 不引用宿主窗口、egui、wgpu 或插件参数对象。它只接受音频缓冲、明确的参数快照和有时间戳的事件。插件适配层将 nice-plug 的数据转换成这些输入。GUI 通过框架参数接口修改参数，通过显示队列读取结果。

音频效果的正确性不得依赖编辑器是否打开。GPU 不进入音频输出的必经路径。内部状态在 `prepare`/激活阶段分配，在运行阶段原位更新。

## 3. 运行生命周期与宿主接口

### 3.1 激活与重置

激活时验证采样率、声道数和固定 FFT 配置，建立 FFT plan、窗口、scratch、环形缓冲、分频权重与固定声部池；显示队列尚未接入。当前 crossover 的干声与湿声共享同一 STFT 帧和输出 ring，无须在该路径另加一条干声延迟线。任何配置无法满足时，应使激活失败并在非实时上下文提供原因。

重置时清空分析历史、输出 OLA、共鸣尾音、音符表和内部采样计数。普通参数变化不得调用整个引擎的 reset。项目加载恢复参数后，尾音从静音开始，不尝试序列化运行中的 FFT 缓冲区或 GPU 纹理。

采样率或质量档位改变时重新准备引擎并重新报告延迟。首版只在宿主允许的停用/重新激活流程中改变 FFT 大小，不在播放期间直接替换 FFT plan 和缓冲区。

### 3.2 音频 I/O

支持 2→2 和 1→1 声道布局，并将 2→2 列在首位作为 nice-plug/CLAP 默认配置。立体声是首个可演奏版本的必备能力：左右分别保留分析历史、FFT 缓冲、OLA 输出和复数共鸣状态；两侧共享只读的 crossover 权重、目标频率及衰减控制。每个声道的输出只由该声道输入及该声道状态产生；不得先混为单声道再复制到左右，也不得在分频混合时把左右声道交叉接线。单声道实例只分配和处理一个声道。

插件声明 2→2 与 1→1 布局，M1 的流式 STFT 已为左右分别分配输入与输出 ring，增益链路对两路应用同一个平滑控制值，没有求和或复制声道。nice-plug 将第一个布局作为默认配置；M2 构建曾把 1→1 放在首位，可能导致音频宿主默认选择单声道。现已改为 2→2 优先，源码检查确认左右不同输入在 crossover 链路中互不影响；宿主是否实际协商为 2→2 仍需新版音频宿主验证。

内部处理使用 f32，离线参考计算可使用 f64。宿主提供的块长与 FFT 长度无关，应能处理 1、7、64、127、128、257、512、1024 等块大小及其混合序列。不能假设每次回调都固定为 128 或正好等于 hop。

### 3.3 延迟和尾音是两个概念

`latency_samples` 表示输入到输出的固定排程延迟。`tail` 表示输入停止后还会产生多久的衰减声音，两者不能混用。

M1 自建流式调度层的 `latency_samples()` 返回 N=4096，并在 `activate` 时报告给宿主。离线脉冲测试在单声道与立体声路径确认了 N 样本偏移，而不是 hop 或 N/2；音频宿主对新版本的实际延迟仍需核对。

报告给宿主的延迟必须与干声内部对齐使用同一个值。宿主 PDC 对齐轨道，不能代替插件内部的干湿对齐；crossover 的干、湿输入也必须处于同一采样时间轴。若采用会增加固定延迟的分频实现，该延迟必须同时进入两条路径和宿主报告。首版不引入带 look-ahead 的 limiter；若以后引入，必须同时更新报告和干声路径。

存在共鸣状态时不能提前向宿主声明休眠。根据固定的尾音截止阈值和最长衰减，选择框架合适的尾音/继续处理状态。暂停、seek、宿主 bypass、内部 bypass 和 reset 分别验证，不假定它们具有相同语义。

## 4. M1：透明 STFT

### 4.1 配置与时间含义

开发基线暂定 N=4096、H=512，先保持固定。测试另覆盖 2048/256 和 8192/1024。下表以 48 kHz 为例：

| N / H | FFT 频点间距 | 分析窗口覆盖时间 | 更新间隔 |
| --- | --- | --- | --- |
| 2048 / 256 | 23.4375 Hz | 42.67 ms | 5.33 ms |
| 4096 / 512 | 11.71875 Hz | 85.33 ms | 10.67 ms |
| 8192 / 1024 | 5.859375 Hz | 170.67 ms | 21.33 ms |

频点间距为 `fs/N`，不是任意条件下能分辨两个正弦的保证。补零使频谱采样更密，不增加真实观察时间。更新间隔 H/fs 不等于端到端延迟。以上配置尚不是承诺满足现场演奏延迟的最终选择。

### 4.2 透明处理公式

使用局部帧坐标，定义：

```text
X_m[k] = FFT{ x[mH+n] · w_a[n] }
z_m[n] = IFFT{ X_m[k] }
y[t]   = Σ_m z_m[t-mH] · w_s[t-mH] / D[t]
D[t]   = Σ_m w_a[t-mH] · w_s[t-mH]
```

这里只描述信号的数学对齐，实时实现要在完整帧到齐后排程输出，并计入固定延迟。初始补零和结束冲刷必须包含在测试中。

建议以 periodic Hann 的平方根作为分析窗和合成窗起步。对 N/H=8 的稳态重叠，其窗乘积之和为 4；不要把这个常数不加检查地套到其他窗口或重叠率。首版可以预计算一个 hop 周期的归一化表，并验证所有位置分母均为正。

RustFFT/RealFFT 的前向与逆向默认不自动构成单位增益往返，需要统一约定逆变换后乘 `1/N`。这个 FFT 归一化与 OLA 的窗重叠归一化是两件事，只能各应用一次。

如果使用实数 FFT，正频率缓冲长度为 N/2+1。DC 与 Nyquist 的虚部应满足实数信号约束。若使用完整复数频谱，负频率由共轭对称关系构造，不可只写正频率后把负频率留作随机旧数据。

### 4.3 缓冲和 scratch

每个声道各有输入 ring 保存分析历史，并各有输出 ring 保存尚未交给宿主的 OLA 结果。输出槽被消费后应清零，避免旧帧在环形缓冲回绕后再次叠加。所有 ring、窗和 FFT 缓冲在激活时分配。不可变的 FFT plan 与窗系数可以共享；逐声道顺序处理时 scratch 可以复用，但必须在处理下一声道前取走当前声道的结果，分析历史与 OLA 状态不能复用。

按具体 plan 查询并预分配前向和逆向 scratch，使用 `process_with_scratch`。不能从上游示例某个 FFT 长度恰好不需要 scratch 推导出所有长度都可以传空切片。不要在音频回调中调用会临时分配工作空间的简便接口。

M1 评估了 nice-plug 的 `StftHelper`。直接使用它会让纯 DSP crate 依赖框架，且其公开缓冲构造接口不便于编写无 `unsafe` 的独立流式测试，因此在 `spectral-dsp` 中实现了预分配的逐声道 ring 调度。每个声道拥有独立输入与 OLA 输出 ring；FFT plan、窗和临时计算缓冲顺序复用。透明处理与离线参考遵守同一套窗口、FFT 归一化和时间原点。

## 5. M2：整数频点共鸣研究模型

M2 用于验证频谱记忆、衰减与相位，不作为最终调音方案。0.3.0 / 0.4.0 对于正频率整数 bin k 的模型是：

```text
R_m[k] = p_k · R_(m-1)[k] + b_k · X_m[k]
p_k    = r_k · exp(j · 2πkH/N)
r_k    = 10^(-3H / (fs · T60_k))
b_k    = g_k · (1 - r_k)
```

`r_k` 使旧状态每经过 T60 秒，幅度下降到 0.001，即 -60 dB。旧版相位旋转对应频率 fk=k·fs/N 在 H 个采样间隔内继续振动。0.4.1 对选中 bin 改用 `p_k=r_k·exp(j·2π f_h H/fs)`，其中 `f_h` 是目标泛音频率；输入投影和 IFFT 合成仍使用最近 bin，故这只是针对湿声抵消的修正，不能作为 M3 音准验收。只保留幅度而不推进相位，会改变合成结果和连续性。立体声时公式对 L/R 分别运行，`R_m,L[k]` 与 `R_m,R[k]` 是两套状态；衰减系数可以共享。

`g_k` 控制输入激励，`1-r_k` 是针对定常同频输入的增益校准起点。它会让不同衰减设置下短脉冲的激励强度变化，因此最终产品仍需进行激励电平与响度校准，不能把这个系数当成全部音色设计。

以下 Rust 代码是单状态的简化算法草图；当前已编译的实现位于 `crates/spectral-dsp/src/bin_resonator.rs`，并由现有流式 STFT 调度。草图依赖外部在初始化时验证参数，不包含完整 FFT、窗口和宿主逻辑：

```rust
use num_complex::Complex32;

pub struct BinState {
    state: Complex32,
    propagation: Complex32,
    injection: f32,
}

impl BinState {
    pub fn step(&mut self, input: Complex32) -> Complex32 {
        // 旧共鸣继续转相位并衰减，新输入在这一帧增加激励。
        self.state = self.propagation * self.state + self.injection * input;
        self.state
    }

    pub fn reset(&mut self) {
        // 只在引擎明确重置时清零，普通参数更新不抹掉尾音。
        self.state = Complex32::new(0.0, 0.0);
    }
}
```

反馈半径必须严格小于 1；系数更新需要有限值检查和过渡策略。把未激励的 bin 输入置零时，其旧状态仍应继续衰减。显示关闭不能重置这些状态。

M2 已将正频率状态和共轭镜像送入 IFFT，经现有 WOLA 重建。0.3.0 版本逐声道叠加到延迟 `N` 样本的干声；后续 0.4.0 改为在同一 STFT 帧内执行三频段 crossover。宿主可见的 `Root Note`、`Decay T60` 和 `M2 Wet Level` 仍是整数频点研究原型控制。M2 只保证整数频点上的模型性质：在 48 kHz、8192 点 FFT 下，将 110 Hz 吸附到最近频点会变为 111.328125 Hz，约高 20.8 音分。因此“M2 会响”不能作为 M3 音准验收。

## 6. M3：精确频率与频谱重建

### 6.1 目标、固定限制与证据边界

M3 的目标是让每个泛音在实际目标频率上继续振动，同时保留输入频谱对其激励的控制。首版基音来自固定十二平均律音符表，暂不加入实时任意 Stretch 或连续 pitch bend，以便预计算频谱模板并限制回调开销。

目标频率为：

```text
f0(note) = 440 · 2^((note - 69)/12)
f_h     = h · f0, h = 1..K
ω_h     = 2π · f_h / fs
```

高频泛音在到达 Nyquist 之前平滑减弱，设计基线在 0.45fs 开始进入上限保护范围。具体过渡带在音色测试后固定；禁止把超出上限的泛音折回可听频段，或全部钳在同一个最高频点。

以下分数频率模型是本项目的设计候选。M3 必须用离线参考和实时原型验证后才能冻结算法，不把数学可表达当成已经满足音色或 CPU 预算。

### 6.2 高精度输入投影参考

对每个目标频率计算局部帧的复数投影：

```text
D_m[h] = (2 / Σ_n w_a[n]) · Σ_n x[mH+n] · w_a[n] · exp(-jω_h n)
```

这条直接求和公式用于离线参考，不是要求实时版对每个声部逐次做 N×K 的求和。它给出包含幅度和相位的激励参考，避免把“取最近 bin 的幅度”误当成精确频率分析。实信号的负频率泄漏、低频窗口不足及相邻分量干扰仍存在，必须通过测试表征；该归一化不意味着任意输入都能被完美拆分。

实际版共享每声道的一次 FFT，再估计目标频率的复数投影。可评估基于窗函数的复数插值、相位声码器式分析或有限支撑近似。不能只线性插值两个幅度，再任意附上某个 bin 的相位。

频谱平滑是可选的激励整形：它可扩大一个泛音接收输入能量的频带，也会混合邻近成分。M3 先验证无额外平滑的投影，再对可控带宽的平滑做 A/B。逐泛音的衰减记忆与频率轴平滑是不同模块。

### 6.3 精确泛音状态

对于目标频率固定的一个声部：

```text
R_m[h] = r_h · exp(jω_h H) · R_(m-1)[h]
         + a_h · (1-r_h) · D_m[h]

T60_h = clamp(T60_base · damping(f_h), T60_min, T60_max)
r_h   = 10^(-3H / (fs · T60_h))
```

`R_m[h]` 的相位以第 m 帧的局部起点为参考。改变分析帧原点或合成帧原点时必须同步换算相位。MIDI Gate 关闭激励时令输入项为零，但保留已有状态衰减。

每个音符生命周期内的目标频率保持固定。0.5.x 曾使用两套单音状态淡入淡出，0.6.0 改为固定 8 声部池：普通换音让旧状态自然衰减，仅在满额抢占时短淡出。后续滑音需使用随时间积分的相位，并验证频谱模板更新过程，不能每帧清零相位。

### 6.4 精确合成参考与 IFFT 路径

离线的直接时域参考为：

```text
u_m[n] = w_s[n] · Re{ Σ_h R_m[h] · exp(jω_h n) }
```

它用于产生可比对的参考结果。产品目标仍是构造等价的频谱再 IFFT，而不是悄悄将产品改成另一套时域合成器。

定义合成窗的 DTFT：

```text
W_s(θ) = Σ_n w_s[n] · exp(-jθn)
Ω_k    = 2πk/N
```

那么该帧完整的目标频谱可以写为：

```text
U_m[k] = 1/2 · Σ_h [ R_m[h] · W_s(Ω_k - ω_h)
                  + conj(R_m[h]) · W_s(Ω_k + ω_h) ]
```

这个表达式解释了为什么一个不在整数 bin 上的正弦通常要分布到多个频点，以及为什么负频率共轭项、相位和窗函数都不能省略。先用全频谱参考验证 IFFT 与直接合成一致，再评估有限宽度模板、查表和批量累加。

**该精确泛音路径与透明 STFT 路径的归一化不同。** 上式已经包含合成窗，IFFT 后不得再次乘同一个窗。直接泛音重建的 OLA 分母为 `Σ_m w_s[t-mH]`；透明 STFT 的分母为 `Σ_m w_a[t-mH]·w_s[t-mH]`。分析投影的幅度校准也要单独计算，不能把三个缩放因子混成一个经验常数。

### 6.5 从参考实现到实时实现

按如下顺序优化，每一步都与前一阶段的参考比较：

1. 用 f64 直接投影和直接正弦叠加建立离线参考，先验证单泛音与固定频率。
2. 用完整 W_s 模板构造频谱并 IFFT，与参考比较相位、振幅和 OLA。
3. 对模板采用有限支撑近似，扫过不同分数 bin 偏移、频率和相位，确定可接受误差。
4. 激活时为支持的音符、泛音和采样率预计算静态模板；MIDI note-on 只选择模板并分配预留状态。
5. 优化输入投影，复用每声道 FFT；将其误差与合成近似误差分别测量。
6. 最后才增加复音、SIMD 和音色调制，并重新测量 CPU 高分位耗时。

若有限支撑模板不能满足音准、音色或 CPU 门槛，应保留对比结果并修改方案。不能用更平滑的 UI、最近 bin 吸附或未经说明的另一种合成器掩盖失败。

### 6.6 0.5.0 的实际实现

插件已切换到 `spectral_dsp::SpectralResonator`。旧 `StreamingStft` / `BinResonator` 保留为 M1/M2 回归基线，不再是插件的湿声路径。

M3 对每个声道的原始帧做一次 FFT。激活时为 MIDI 33–93 预计算周期 Hann 的复数 DTFT 模板，原上限 64 泛音，0.6.1 扩至 1024，0.8.0 改为 512；始终仅建立低于 `0.49 × 采样率` 的有效模板。每个模板保留最近 bin 两侧各 32 个 bin，共 65 点。用 Parseval 关系将模板与原始 FFT 做复数内积，得到分数频率的窗内投影；模板的实部和虚部都参与，不能替换成幅度插值。衰减状态的相位按真实目标频率推进。

湿声把同一 Hann 模板按共鸣状态叠加，再加入共轭负频率项。干声通过 `0.5 X[k] - 0.25 X[k-1] - 0.25 X[k+1]` 得到乘 Hann 窗后的频谱。两者使用同一个中频权重，合并后执行一次 IFFT。M3 此处使用 Hann + 矩形合成，与 M1 的 sqrt-Hann WOLA 不同；每帧的输出缩放为 `2H/N²`，来自 IFFT 的 N 与 Hann 叠加分母 `N/(2H)`，不再额外乘窗。环形调度保持 N 样本报告延迟。

左右声道拥有独立状态。0.5.x 的两套单音状态会在换音时约 20 ms 淡出旧音，已由 0.6.0 的 8 声部池替代。各声部在每个 hop 独立累计 Gate 与力度，普通 note-off 只关闭激励，既不改旧状态相位，也不强制缩短 T60。新音符短淡入后经 Hann 重叠相加；满额抢占及待启动音符规则见第 8.3 节。

Gate 在输入样本处累计当前音符的力度，在 hop 边界换算为该音符的平均激励量。64 样本短 Gate 有回归测试；同一 hop 的多个不同音高只选择最终音符。投影仍覆盖完整 N 点历史，不能宣称逐样本隔离音符前后的激励。自然松键保留尾音；Choke/CC120/Panic 淡出指定状态或全部湿声，历史 OLA 输出随固定管线排空。

完整 f64 频谱/IFFT 与直接正弦参考、稀疏模板误差、实际输出音准/T60、MIDI 事件跨块一致性及音频回调无分配检查均有测试。测试范围和本机耗时见验证记录；不存在对全部采样率、全部素材或宿主长时间运行的保证。

### 7.1 M3 参数表

参数 ID 是工程兼容性的一部分。显示名称可以翻译，ID 发布后不能随意更改。下面的范围和默认值属于待试听的初始设计。

0.5.0 已实现表中的内部/MIDI 音高、泛音数量、阻尼和激励控制。为保留已有工程，输出增益仍使用原 ID `output_gain`，线性范围 0–2、默认 1，暂不改成表中的 `output_gain_db`。湿声增益仍用 ID `m2_wet_level`，仅把显示名改为 Wet Level，范围 0–16、默认 4。旧值不会被默认值覆盖，未加入隐藏限幅。分频点和 T60 当前仍采用原有线性参数平滑；表中对数平滑是后续校准项。

FFT 质量档位先作为非自动化的引擎配置；首版不允许播放中改变延迟。MIDI 模式各声部独立 Gate：有音符时允许新激励，松键后停止该声部的新激励但保留尾音，踏板可延长 Gate。内部模式持续接受音频激励。

### 7.2 阻尼曲线的具体起点

以第四泛音为暂定转折点，定义 `q_h = log2(f_h/(4f0))`。一个可测试的初始曲线为：

```text
damping(f_h) = 2^(-2·hf_damp·max(q_h,0)
                  -2·lf_damp·max(-q_h,0))
```

两项为零时，所有泛音拥有相同 T60。高频阻尼增加时，高于第四泛音的部分更快衰减；低频阻尼增加时，低于第四泛音的部分更快衰减。这是本项目自己的映射，M3 通过听感和测量决定是否保留。

T60 必须限制在有效范围内再换算半径。不要直接平滑一个可能越过单位圆的任意复数反馈系数。极小状态在足够低的阈值下归零，例如幅度低于 1e-20 时结束其状态；该阈值远低于正常音频动态，并用于限制次正规数及无限拖尾。

### 7.3 三频段 crossover、干湿路由与增益

两个分频点形成低／中／高三个**频率**区域。低频和高频的湿声受抑，干声继续输出。0.5.1 按用户要求增加中频 Mid Mix（参数 ID `mid_mix`），将中频干声与共鸣湿声线性混合；默认 100%，延续 0.5.0 的路由。没有低、高频独立 Mix 或全局 Mix。两个分频点至少相隔一个八度；在采样率变化或自动化输入越界时保持有效顺序。

定义 `d_c(t)` 为已延迟到湿声时间轴的第 `c` 声道干声，`w_c(t)` 为同一声道湿声，`M` 为中频带通算子，`A` 为三频段共同的全频参考路径。`A` 包含共同且已报告的固定延迟。令 `q=mid_mix/100`，`g=wet_level`，路由为 `L(d_c) + M((1-q)d_c + q·g·w_c) + H(d_c)`，等价为：

```text
y_c(t) = output_gain × [A(d_c(t)) + q × M(g × w_c(t) - d_c(t))]
```

当 `q=0` 时，输出退化为延迟对齐的全频干声乘输出增益；当 `q=1` 时保持 0.5.0 行为。当 `g·w_c=d_c` 时任意 q 均应保持共同参考路径。中频要接近纯湿声，还要求通带的 M 在幅度和相位上接近 A。M 对两个输入使用同一权重和时间基准；同一 Hann 窗频谱中实际计算 `Y_c[k]=(1-q·M[k])X_c[k]+q·M[k]·g·U_c[k]`，随后共用 IFFT 与 OLA。采用线性权重，避免相同信号在混合中点额外增益。不增加延迟、分配或跨声道运算。Mix=0 时共鸣状态继续接受激励和衰减，回调不做 reset。

新增参数在旧预设缺失时由 `filter_state` 补成 100%，已有值保持不变。宿主参数以百分数保存，DSP 接收 0–1；20 ms 线性平滑在逐样本回调推进，hop 边界取值，与分频控制共用原有时序。Wet Level 继续是湿声增益，因此设为 0 并不自动恢复全部中频干声。

当前 `M[k]` 使用两个六次幂过渡函数相乘，令 `u=f_k/low_mid_hz`、`v=f_k/mid_high_hz`：`M[k]=[u^6/(1+u^6)]×[1/(1+v^6)]`。两个边界在通带外分别趋近约 36 dB/oct 的衰减，并保留有限宽度的过渡带：从低频走向中频时，湿声权重逐渐增大；从中频走向高频时逐渐减小。`-36 dB/oct` 是离开转折区后的渐近斜率，不表示 200 Hz 到 300 Hz 必然恰好相差 36 dB。离散 FFT 频点、分析窗口及不同干湿声的相位仍可能影响实际响应；应记录扫频和听感，不用“互补”一词代替测量。

当前分频点参数以约 50 ms 平滑，宿主事件位置更新目标值，但权重表只在下一个 hop 使用最新平滑值重算，因此音频生效时间量化到至多一个 hop。频谱重组不插值高阶 IIR 系数，且回调期间不分配新缓冲。首版不承诺整个频谱共鸣引擎逐样本改变音高；分频控制与其事件时序分别验收。

Input Send 只影响进入共鸣器的激励，不改变旁路干声。正常的共鸣累加需要保留电平余量；增加泛音或复音时的归一化规则应确定、可测，并经过平滑。输出保护不能代替反馈稳定性。

透明测试时关闭所有非线性输出保护。首版仅做非有限值检测和明确的异常处理；需要柔和限幅时作为单独、可关闭的模块加入并验证音色，不隐藏在 FFT 归一化系数中。

### 7.4 持久化

状态保存至少包含 `state_version`、所有可恢复参数、固定引擎配置和编辑器尺寸。使用框架支持的序列化和稳定参数标识，不保存绝对临时路径、音频历史、运行中的声部相位或 GPU 句柄。

0.5.0 当前使用 nice-plug 的 `PluginState.version`（包版本）和稳定参数 ID，尚无独立状态 schema 或编辑器尺寸。`filter_state` 给旧预设缺失的新参数插入确定默认值，避免加载进已切到 MIDI 模式的实例后遗留旧值；保存过的新参数不覆盖。未来版本拒绝与完整状态 schema 迁移仍归 M6，不能把当前默认值补齐称为完整迁移体系。

每次引入不兼容变化都增加状态版本并提供迁移。无效值进行有界回退；无法识别的未来版本需要明确报告，不能部分加载后伪装为完全恢复。CLAP ID、后续 VST3 Class ID 和参数 ID 在首次分发前固定，并写入版本记录。

## 8. MIDI、自动化与复音

### 8.1 事件时序

保留宿主事件的样本偏移。增益和分频点等控制在事件位置接收新目标值并平滑；首版共鸣音高变化以 hop 边界应用，需要在文档和测试中明确其最多一个 hop 的控制量化，不能仅因为框架支持 sample-accurate automation 就宣称全部频谱参数都做到逐样本生效。

分析帧、参数事件和合成输出必须使用同一输入采样时间轴。事件先映射到约定的帧边界，再通过引擎固定延迟排程到输出；不能在不同层各补一次延迟。M3 需要用已知时间点的音符与脉冲测量事件到输出的实际关系。

帧内窗长造成的时间混合仍然存在。若将来需要精确到单采样的门控，需在分析前或合成包络中增加相应处理，不能仅缩短 hop 后声称长窗口完全没有时间模糊。

### 8.2 音符身份和松键

0.6.0 将 M3 的最后音符优先改为独立音符事件。`MidiNotes` 使用 128 个固定身份记录，区分 channel/key、CLAP voice ID 和内部递增 token；每次 note-on 产生独立声部，重复同音也可重叠。松键或零力度 note-on 关闭匹配声部的激励；踏板按住时延后到踏板释放，其他音符持续共振。已释放的身份记录保留供后续 Choke 匹配；记录满时先回收最早的已释放记录，否则最早的按住记录，并淡出对应旧声部。

应正确区分重复同音音符，以及 MIDI channel/key 与 CLAP note ID 的识别语义。框架事件中的 note-off、choke、all-notes-off、持续踏板与设备断开不能造成悬挂音。Panic 是明确的用户操作：短淡出后清空声部，避免正常操作时突然截断高电平尾音。

超出首版支持基音范围的音符采用明确的忽略策略，并在文档中写明；不要悄悄钳到边界音符而改变旋律。速度信息用于控制激励增益，不直接修改输入干声。

### 8.3 0.6.0 固定复音池

0.6.0 使用 8 个固定声部，0.6.1 将每声部上限从 64 扩至 1024 泛音，0.7.3 将固定声部池扩至 16。左右独立，共享各声道输入 FFT 与最终 IFFT。上限包含松键后的尾音。每个声部保存复数泛音状态、Gate/力度、身份、上次渲染的状态能量与启动顺序。空闲槽直接使用；已释放且状态能量低于 `1e-16` 的槽在 hop 结束回收；按住的静音声部继续保留，以接受之后的输入。

池满时选择未在淡出的声部中能量最低的已释放尾音，否则选择最早按下的声部。先关闭其激励，以约 20 ms、按 hop 量化的增益斜坡淡出，再启动存于该槽的待替代音符；不能直接重写仍可听见的复数状态。48 kHz 下满增益声部经过两个 hop 淡出，等待最长约 21.33 ms，之后仍有新声部淡入和原有 STFT 时间混合。只有抢占会引入这段额外启动等待，报告延迟仍为 4096 样本。

每槽最多一个待启动音符；全部槽都在淡出时，最新事件替换最早的待启动音符，保留当前淡出进度。待启动音符同样响应 note-off、踏板后的 Release 和 Choke；短音符已累积的 Gate 保留，首次注入最多一个完整 hop，避免等待导致增益突增。Panic 清除所有待启动音符并淡出当前状态，保留已对齐的干声；host reset 才清空所有音频历史。切换模式或 Panic 重置 MIDI 记录时不重用 token，防止新音符误匹配正在淡出的尾音。

各声部湿声直接相加，干声只混入一次。不随活动声部数量自动缩放，因此新音符不会调低旧尾音，单音电平不变；和弦峰值可能上升，由 Wet Level / Output Gain 管理余量，没有隐藏限幅。0.6.1 最大声部状态预算为 `8 × 1024 × 2` 个 f32 复数，即 128 KiB，不含模板和 FFT 缓冲。声部池在激活时分配为固定长度堆存储，避免把整个扩大的池放到宿主音频线程栈上；note-on、抢占和 reset 都原地复用，回调不分配或释放。合成使用二次幂 FFT 的位掩码处理共轭镜像索引，避免每个模板点执行除法。39 项源码测试包括 192 kHz 下 8×1024 泛音事件压力与 reset 零分配。

处理负载约随有效泛音数、声部数、Unison 和声道数增加。设置总泛音预算并清楚定义超额策略，不能在 CPU 紧张时静默丢弃随机泛音或音符。复音参数调制和 MPE 只有在真正实现每声部参数与事件映射后才能开启相应能力声明。

### 8.4 音频宿主接线验证

首版作为接收音符的 Audio Effect 导出。先在音频轨道上加载，再在其前方通过 MIDI 路由 接收另一轨道的音符。验证有音频无音符、有音符无音频、两者同时存在，以及轨道静音/停止等情况。

这描述的是计划验证的路由，不代表已在本机完成操作。测试记录必须包含音频宿主实际版本、插件格式、采样率、缓冲大小和具体路由。

## 9. Rust 内存安全与实时线程契约

### 9.1 自有代码边界

`spectral-dsp` crate 使用 `#![forbid(unsafe_code)]`。插件导出宏、操作系统窗口与 GPU Surface 可能通过上游包含必要的底层不安全操作；它们不混入 DSP crate。自有底层代码如确实需要 unsafe，必须在独立适配模块解释生命周期和别名不变量，再决定是否接受。

Rust 的类型与借用检查不能自动阻止堆分配、锁竞争、长时间计算、panic 或高成本析构。不能以“使用 Rust”代替实时验证。

### 9.2 音频回调禁止事项

- 不创建或扩容 Vec/String，不创建 FFT plan，不分配 Shader/纹理，也不切换全局运行时。
- 不获取可能等待 GUI/后台线程的 Mutex/RwLock，不使用阻塞 channel。
- 不读写磁盘、网络或格式化日志，不调用同步 GPU readback，不等待渲染完成。
- 不在回调内释放最后一个拥有大型缓冲、GPU 资源或工作线程的 Arc。
- 不对运行时输入使用无条件 `unwrap`/`expect`；长度和状态不变量在 prepare 时确认，运行错误采用预先定义的有界处理。

诊断使用无分配的计数器；后台或 UI 再格式化信息。若检测到 NaN/Inf，应记录计数并局部清理异常状态，输出有限值，避免让一个错误无限传播。故障路径不能依赖当场拼接字符串或写文件。

### 9.3 GUI 数据交换

采用预分配、固定容量的 SPSC 队列。音频线程用非阻塞 try-push 发布帧；满时丢弃本次显示帧并增加计数。消费者尽快排空队列，实时曲线取最新一帧；历史频谱按时间戳聚合或明确留下缺口。

生产者不能直接推进消费者读指针来“覆盖最旧帧”，除非所选队列明确提供且证明该并发语义。两个数组加一个原子索引也不自动构成安全的双缓冲：写者不能覆盖读者还在访问的数据。

每个显示帧包含序号、采样时间、采样率、FFT 长度及有效数据长度。缓冲容量在激活时按最大 N 分配，不随 UI 尺寸变化。GUI 关闭时停止生成不必要的可视化数据，但音频处理状态保持。

输入与湿声显示的时间标签要明确，湿声的显示位置应与处理延迟一致。立体声合并显示采用能量或明确的声道选择，不使用可能因反相而完全抵消的简单 L+R 幅度作为唯一显示依据。

## 10. GPU 界面与可视化

### 10.1 参数编辑与绘制分工

egui 负责控件与交互，参数修改必须经过框架提供的 begin/set/end gesture 等机制，使宿主自动化与撤销能够识别操作。界面不直接拿到 DSP 的可变引用。

频谱、泛音位置、调制动画使用独立渲染模块。首版 GPU 实验以 60 FPS 为目标，提供降低帧率或停止动画的选项。窗口不可见时减少绘制，多实例下避免每个窗口都无限制重绘。

### 10.2 频谱历史纹理

GPU 持有固定尺寸的历史纹理。每次有新频谱，只更新必要的一列或一行，循环推进写入位置；Shader 通过纹理坐标呈现滚动，并把强度映射为颜色。不要每帧在 CPU 重画和上传整张历史图片。

可视化频率轴可以采用对数刻度。它只是显示映射，不将普通 FFT 变成 CQT。CPU 或整理线程按像素宽度聚合频谱；波形显示按像素列的 min/max 保留峰值，不将整段采样点逐个作为 UI 对象。

显示平滑与 DSP 衰减分别设置。每秒 60 次绘制可以插值较低频率的分析数据，但不会降低分析窗口长度或增加真实频率分辨率。频谱标签要明确显示的是输入、湿声重建前，还是最终混合输出，不能将不同位置混为一谈。

### 10.3 插件窗口生命周期

优先使用 nice-plug/egui-baseview 的嵌入接口和匹配版本示例。GPU Surface 与宿主窗口的生命周期绑定；编辑器关闭时先停止相关绘制，再在适当线程释放资源。不能让音频线程等待窗口关闭，也不能在宿主窗口已销毁后继续使用其句柄。

M5 覆盖缩放、DPI、快速反复开关编辑器、多实例、图形设备丢失与隐藏窗口。wgpu 后端实际可用性需要在目标机器上验证，不能将框架列出后端等同于本插件已经测试通过。

| 精确音高 | 单泛音测试 55、110、220、440、1760 Hz 等目标 | 稳态误差 ≤1 音分；使用足够长信号和正弦拟合/相位回归，不能只取最大 FFT bin |
| 衰减 | 脉冲或短噪声激励后关闭输入，拟合对数包络 | T60 估计误差 ≤max(设定值的 5%, 一个 hop)；排除启动与数值噪声区域 |
| 稳定性 | 最大激励、最长衰减、静音长跑与参数边界 | 无 NaN/Inf、无状态无界增长、无无限挂起尾音 |
| MIDI | 重复同音、快速换音、松键、持续踏板、Panic | 行为符合单音/复音规则；无悬挂音；时序量化与声明一致 |
| 参数恢复 | 保存、关闭、重开工程与多实例不同参数 | 参数、引擎配置和状态版本正确恢复，运行中的尾音按约定重置 |
| 实时内存 | 调试分配检测与回调路径审查 | 稳态和事件压力下回调没有堆分配或非预期阻塞 |
| 编辑器隔离 | 开关、隐藏、缩放、拖动和多个编辑器 | 音频结果不依赖窗口存在，DSP 不等待绘图 |

透明重建的幅度误差门槛以输入峰值不超过 1 的测试信号为基准。精确音高重建的误差与“相邻两个输入频率能否被分析区分”分别报告；合成频率准确不证明低频分析具有无限分辨率。

最小测试矩阵为 44.1/48/96 kHz，单声道/立体声，三种 N/H 配置，以及可变块长。立体声测试必须保留左右各自的输入与输出记录，不能只比较折叠后的单声道波形。M1 不必等待完整音色功能才开始自动化测试。

### 11.1 性能测量

先记录基准机器、CPU、电源模式、操作系统、音频宿主版本、构建模式和插件配置。Release 测量回调 p50/p95/p99 与最大耗时，不只读宿主平均 CPU 百分比。

回调截止时间为 `block_size/fs`。初始目标是在 48 kHz、128 点、单实例、单声部、64 泛音的基线下，p99 不超过该截止时间的 50%，最大值不超过 80%，并在至少 10 分钟播放中无音频 underrun。M3 与 0.6.0 已分别测量单音/8 声部的短时离线引擎耗时，见验证记录；音频宿主实时回调和至少 10 分钟播放尚未验收。

FFT 的突发运算可能集中在某一次小块回调中，因此平均耗时低仍可能超时。需要记录恰好触发分析/重建的回调，必要时调整调度或算法，不通过丢音频来降低统计值。

GPU 编辑器以稳定 60 FPS 为初始目标，同时报告 p99 帧时间与最差停顿；首轮门槛暂定 p99 ≤25 ms。测量打开/关闭编辑器时的音频耗时变化。没有实际 GPU 计时前不宣称 GPU 更省资源。

### 11.2 参考音频与听感

测试素材包括单脉冲、扫频、正弦、双音、固定种子噪声，以及用户有权使用的鼓、人声和乐器片段。听感 A/B 先匹配电平，分别比较瞬态、音准、尾音、金属感、立体声与参数过渡。

若使用 其他产品 作为参考，在合法可用环境中手工匹配可比参数并录制对比。记录 FFT/延迟和内部参数不可知的边界，不把相似听感或某个预设的匹配当成算法等价证明。

## 16. 0.7.0：调制、Unison 与频率衰减曲线

### 16.1 直接控制频率与 T60

`decay.rs` 提供六组 `(Hz, seconds)`。频率限制在 20–20000 Hz，T60 限制在 0.005–12 秒。每 hop 接收经过插件参数平滑的节点快照，在栈上稳定排序；同频节点以原编号较大的为准。插值在对数频率、对数秒数中进行，端点之外保持端点值，避免负衰减或插值过冲。例如 250 Hz/4 秒与 1000 Hz/1 秒之间，500 Hz 为 2 秒。

每个声部以原始 `h*f0` 查询时间，并转换为 `radius = 10^(-3H/(fs*T60))`。因此不同 MIDI 音符只要某个泛音落在相同绝对频率，就具有相同衰减时间；调制输出频率不会反过来改变此查询位置。节点编辑只更新衰减系数，不清空已有复数状态。曲线不变时缓存系数，节点变化或新声部启动时重算。

`Decay Mode=Damping` 保留第 7.2 节的历史规则，`Curve` 使用上述直接时间曲线。两种模式切换时约 20 ms 交叉过渡反馈半径，节点浮点参数另有 50 ms 平滑。Curve 模式不叠加全局 Decay T60 / HF / LF Damp。宿主 tail 报告保守采用全局时间与全部节点时间的最大值，即便当前处于 Damping，也为过渡中的尾音留出空间。0.7.0 阶段在宿主面板编辑节点；0.10.0 已加入第 23 节的图形曲线编辑器。

### 16.2 每泛音的调制与副本

`modulation.rs` 将变化施加到湿声重合成。输入投影与持久共鸣状态保持原始泛音频率，每路 Unison 读取该状态并生成自己的合成相位与频率；没有复制独立失谐的输入投影滤波器。L/R 保留独立音频状态，共用同一组调制轨迹，所以不会串音，也不引入额外声像展开。

| 控制 | 实现语义 |
| --- | --- |
| Off | 关闭调制；Unison=1 时完全返回原重建路径 |
| Chorus | 每泛音/副本使用不同初相的三角波，改变幅度及双极性音高偏移；Rate=0 时音高调制为零、幅度分布冻结 |
| Wander | 每泛音/副本在独立随机目标之间连续线性漂移，幅度及音高随之变化 |
| Granular | 每 hop 以 `1-exp(-rate*H/fs)` 概率独立触发包络，触发后 `grain=1`，随后指数衰减；音高偏移仅向上 |
| Mod Amount / Pitch Mod | 幅度深度 0–100%；音高范围 0–12 半音，实际偏移也乘 Amount |
| Grain Decay | 5–500 ms 指数时间常数，默认 80 ms；不等于 T60 或硬性颗粒长度 |
| Unison / Unison Detune | 1–4 路，均匀覆盖正负 Detune（0–50 音分）；按正在淡入淡出的副本增益之和归一化 |

Granular 是频谱泛音包络调制，不是时域采样颗粒切片。Rate=0 停止新颗粒，现有包络继续衰减；包络输出还有 20 ms 平滑，实际时间形状受 H=512 和 N=4096 的时间分辨率影响。Wander 使用随机目标间插值；这些均为本项目的实现选择。

### 16.3 相位、核函数及实时约束

音高变化同时更新相位和分数频率核。以窗中心为积分参考，使用相邻 hop 频率偏移的梯形积分，再将相位移回当前帧起点；仅旋转原频率的复数状态不足以合成真正失谐的频率。频率与幅度目标用约 20 ms 平滑，效果开关和副本增减使用约 20 ms 淡变。底层共鸣递推不中断，原有尾音保留。

预计算 257 行、每行 65 点的周期 Hann 复数频谱核。运行时对相邻分数 bin 行插值，再平移到目标整数 bin，避免每声部、每 hop 重新计算全部三角函数核。与直接分数频率 Hann 合成对照，测试频率上的最差相对频谱 RMS 为 `2.3054e-5`。上移后的频率接近 `0.49*fs` 时渐弱并排除，不折回频带内。

八个 ModulationBank 及每个 bank 的 1024×4 个 lane 在激活时分配，callback/reset 原位复用。每个 MIDI 声部独立播种，左右共用已准备好的轨迹；声部退休和模式切换不会新建堆对象。泛音减少时仍为原高泛音准备调制，以使其短尾音平滑结束。47 项源码测试含真正 Plugin::process 的模式/曲线切换、可变块、Panic 和 reset 零分配检查；完整结果与性能限制见本版验证记录。最大 8×1024×4 配置成本很高，没有自动降低用户参数或采用 其他产品 的复音共享泛音预算规则。

## 17. 0.7.1：合并镜像频谱写入

在 48 kHz、8 个低音、256 泛音、Granular×4 下，优化前分段计时的湿声频谱重建约占 67%，调制准备和输入投影/状态更新各约 15%，FFT 与混合/IFFT 合计约 3%。因此本轮先优化逐泛音合成，没有更换 FFT 库、缩短核、降低泛音数或移动到 GPU。

原实现为每个泛音的每个核点同时写入正频率贡献及其共轭镜像。利用线性叠加，将所有正频率瓣（包括越过 DC 的循环包裹部分）累加到 `P`，再每声道一次执行 `X[k] = P[k] + conj(P[-k])`。成对读取原值后写回两端，DC 和 Nyquist 单独取两倍实部，保证交叠频瓣也被完整保留。这样将与声部、泛音和 Unison 成乘积关系的镜像写入，变成与 FFT 长度成正比的一次遍历，不增加缓冲。

动态核在不跨数组边界时使用连续切片，移除每核点的循环索引与分散镜像写入，使编译器可以批量处理；跨边界仍使用原有循环索引。完整保留全部 65 点、复数插值与相位。区别只有浮点求和顺序，测试通过标量参考、DC/Nyquist 重合、N=256/4096/16384 及新旧 release WAV 比较约束误差。

`profiling` feature 仅在显式启用时加入分段时钟统计；正常 CLAP 无计时调用。状态更新和合成分为两个循环以便每声部粗粒度计时，保留原声部/泛音的累加顺序。重建之后最主要的三段仍是湿声合成、调制准备、输入投影；FFT 暂不是优先优化项。48 项源码测试、Clippy 全目标/全 feature、两个制品路径的 CLAP 和三轮不带探针 A/B 结果见 [性能记录](validation/PERFORMANCE_2026-09-26.md)。

## 18. 0.7.2：八声部自动 Pan

`voice_spread` 为 0–100% 的宿主参数，默认 0%，带 30 ms 线性平滑。DSP 将归一化宽度乘以新音符的固定位置序列 `[-1, +1, -5/7, +5/7, -3/7, +3/7, -1/7, +1/7]`。索引由音符生命周期的 `order` 决定，不依赖物理声部槽、当前活动数量或音高。第九个新音符重新从最左位置开始；reset 后重新从第一位置开始。松键尾音保持旧 order，等待抢占的音符启动时使用自己的 order，所以其他音符退出或插入不会让尾音位置重新排列。

声部自身另按 hop 限制 pan 变化速度，0 到全偏约 20 ms。输出使用立体声 balance：偏左保持左路增益 1，右路为 `max(cos(abs(pan)*pi/2), 0)`；偏右反之。中心两路严格为 1；单声道强制中心。它不折叠或交叉馈送 L/R，只缩小相反侧湿声，故不会产生额外增益，总功率可能随位置下降；纯左输入也不会被搬到右路。

平衡增益在各泛音输出处乘到声部 gain，再进入原合成路径；共鸣状态、衰减、能量估计和抢占规则保持不变。Unison 副本共同跟随所属音符。干声合成路径不经过 Pan。控制计算每声部每 hop 一次，新增三个 f32 状态/声部，没有增加 FFT、Unison 数或回调堆分配。完整证据见 [0.7.2 验证](validation/VOICE_SPREAD_2026-09-26.md)。

## 19. 0.7.3：8 路 Unison 与 16 MIDI 声部

`MAX_UNISON=8`，宿主参数仍用 `unison_voices`，默认 1；保存的 1–4 值和新增的 8 均按原值恢复。每个泛音在正负 Detune 范围内均匀分布副本频率，维持连续相位，按正在淡入淡出的副本增益总和归一化。8 路减少为较少副本时，退出副本继续短淡出，而不突然移除。输入投影和共鸣状态仍按原始泛音共享。

`MAX_VOICES=16`，上限包含释放尾音。16 个音符各自保留身份和状态；第 17 个音符才需要第 8.3 节的抢占策略。Pan 序列独立固定为原八位置循环，第 9–16 个音符重复该空间排列，不移动已有尾音；Unison 副本仍跟随音符的 Pan。固定池扩大后没有增加输入/输出 FFT 次数，没有增加报告延迟，也没有新增动态复音限制参数。

Windows x86-64 的 `Lane` 实测 72 字节，预分配调制池为 `16 × 1024 × 8 × 72 = 9,437,184` 字节（9 MiB），旧版为 2.25 MiB。`Voice` 为 20,592 字节，十六个共 329,472 字节。这两项较 0.7.2 合计增加约 6.91 MiB，未包含模板、FFT、宿主和分配器开销，不是进程总内存。无论实际使用几路副本，都在初始化时完成这些分配。

新增测试验证全部八路对频谱合成的贡献及归一化；十六声部的输出等于两组八声部输出之和（干声只计一次），松键后十六条尾音仍在；覆盖第 17 个音符抢占、全部待启动槽过载、Spread 位置保留，以及 192 kHz / 16×1024×8 的真实插件 callback/reset 零分配。53 项测试和 CLAP 验证通过。三轮离线测量表明 48 kHz / 256 samples / 16×256×8 在部分场景超过预算，512 samples 下本次测量有余量；完整数据与峰值保留在 [0.7.3 验证记录](validation/UNISON8_POLYPHONY16_2026-09-27.md)，不能用功能检查替代音频宿主实时验收。

## 20. 0.8.0：后处理 Unison 与 512 泛音

`MAX_PARTIALS=512`，新实例默认 256；旧状态中高于 512 的数量钳到新上限。各音符仍按基频和采样率预计算有效模板，48 kHz / 150 Hz 只需 156 个分量，降低容量不会再次减少这一配置的实际合成次数。完整调制 lane 池固定预算从 9 MiB 降为 4.5 MiB，两种算法均预留相同容量，切换不分配内存。

新参数 `unison_mode` 使用稳定枚举 ID `spectral` / `post`，默认及旧状态缺失时均为 Spectral。Spectral 沿用逐泛音副本；Post 在泛音层只准备一份调制/合成结果，对总湿声施加最多八路微移调。每个泛音仍可使用 Chorus / Wander / Granular，但 Post 副本共享已生成的调制，因此声音与 Spectral 不同。Voice Spread 仍在 MIDI 声部层工作，左右音频保持独立。

`post_unison.rs` 将每路音分 c 转为速率 `r=2^(c/1200)`，读取 `x[n-d[n]]` 并令延迟增量 `Δd=1-r`。两个读头相隔半个循环，使用互补 Hann 权重衔接 40 ms 延迟扫描的回绕；小数位置采用 16 tap 窗 sinc 插值。缓冲和查表激活时预分配，读速、副本增益及 Post 混合短平滑。Unison=1 或 Detune=0 时移调旁路，历史缓冲持续更新。

每声道将共轭对称干声频谱 D 与湿声频谱 W 打包为 `D+iW`，一次复数 IFFT 的实部/虚部分别得到干湿时域信号，经各自 overlap-add 后只对湿声执行 Post，再求和。每声道每 hop 仍只有一次 FFT/IFFT。Post 输入在 `0.45*fs` 到 `0.47*fs` 间渐弱以保留升调余量；48 kHz 时新增约 0.33–40.33 ms 可变湿声读头延迟，干声仍按原 4096 samples 对齐，尾音报告包括 Post 缓冲长度。

58 项测试及 CLAP 验证通过，覆盖两种算法在 192 kHz / 16×512×8 下的真实 callback/reset 零分配、左右隔离、干声重建、自动化块长无关性、移调频率和旧 Spectral 音频回归。48 kHz / 256 samples / 16 声部 / 256 泛音上限 / 8 路 Unison 的三轮 A/B 中，低音 Granular 持续和弦平均块耗时中位数从 2.1734 ms 降为 0.6296 ms；约 155.6 Hz 起的和弦从 0.9984 ms 降为 0.3689 ms。测试配置、p99、绝对峰值、音色/延迟差别及制品哈希见 [0.8.0 验证记录](validation/POST_UNISON_2026-09-27.md)。以上是本机离线证据，宿主试听与长期实时验收仍待完成。

## 21. 0.8.1：Bounce 模式切换兼容修复候选

用户在音频宿主 6.1 中执行 Bounce 时，界面仍可操作但渲染无法开始。日志显示实时到离线的转换迟迟没有完成。nice-plug 0.4.2 在激活状态下切换 render mode 会调用宿主 `request_restart()`；本插件不依赖处理模式，能够省略这次额外握手。新增默认开启的框架策略 `CLAP_REACTIVATE_ON_RENDER_MODE_CHANGE`，仅本插件设为 false，仍记录模式并保留其他正常激活流程。没有更改 DSP，也没有限制为实时导出。

框架源代码保存在 `vendor/nice-plug`，仅两处上游源文件变更，通过根 Cargo.toml patch 引用。实际 CLAP ABI 测试在旧版复现模式切换重启请求，新版请求次数为零；Spectral/Post 分别在四轮模式切换中保持音频和状态一致，跨版本同算法音频哈希也相同。58 项源码测试与 CLAP 验证通过。尚未获得音频宿主挂起线程栈或修复后的 Bounce 成功证据，因此保持“候选修复”的结论。完整记录见 [0.8.1 验证](validation/BOUNCE_TRANSITION_2026-09-27.md)。

## 22. 0.8.2：有限尾音调度与双线程模拟 Bounce

用户反馈 0.8.1 仍挂起。扩展实际 CLAP ABI 模拟宿主，将主线程状态保存/延迟查询与音频线程处理并发运行，反复执行录制标志、停止输入、尾音等待、停止/重置、状态恢复、离线切换和不同采样率下的重新激活。没有复现显式 stop/state/activate 的死锁，但旧版静音后始终返回 CONTINUE，不能让按 CLAP 状态等待尾音结束的调度器完成暂停。

0.8.2 将 `ProcessStatus::Tail` 映射为 `CLAP_PROCESS_TAIL`，并在长度改变时从音频线程调用可选 `clap_host_tail.changed()`；先发布新值并释放插件锁，再通知宿主，使其可以立即回查。DSP 和尾音时长公式不变。四个 Internal/MIDI × Spectral/Post 配置共 12 次模拟离线渲染通过，与 0.8.1 的原始音频哈希逐份相同。58 项源码测试与 CLAP 验证通过。模拟调度器不等同于音频宿主内部实现，实际 Bounce 修复确认仍待用户环境结果。详见 [0.8.2 记录](validation/BOUNCE_TAIL_2026-09-27.md)。

## 23. 0.10.0：紧凑控件、衰减图与帧率

`editor_controls.rs` 将显示格式与宿主参数分开。读数最多五位有效数字；进入编辑时取未调制参数的完整值，只在内容确实改变且提交时调用宿主 setter。单位解析支持 Hz/kHz、百分比和 dB。Wet Level / Output Gain 的 GUI 使用 `20*log10(gain)`，输入使用 `10^(dB/20)`，存储与宿主自动化仍使用原线性参数和范围。旋钮从约 −60 dB 到原参数最大增益，最低端精确静音；文本可输入更小的有限增益或 `-inf`。整数旋钮独立累积归一化拖动量，避免慢速和 Shift 拖动每帧被取整吞掉。所有手势在释放、隐藏或关闭时配对结束。

常用的分频、Middle dry/wet、Wet Level、Output Gain 固定在图下；其余分为 Resonance、Decay Curve、Motion / Unison、Routing。Pitch Source=MIDI 时隐藏 Root Note 并显示 Maximum Polyphony。隐藏只影响绘制，不改宿主状态。图中分频线默认低亮度，悬停/拖动时显示自动测宽且约束在图内的提示；其他位置显示鼠标频率。新增窗口高度仍全部分配给频谱。

`editor_curve.rs` 调用公开的 DSP `DecayCurve::prepared/seconds_at` 和从原公式提取的 `damping_seconds`。Damping 基于泛音阶数，以第 4 阶为阻尼支点；其图用基频倍数作横轴。Curve 用绝对 Hz 为横轴，六节点可拖动或选中后精调。节点频率可交叉，编号身份不变，排序和同频规则由原 DSP 负责。两种模式的目标曲线与音频计算相同，短参数平滑的瞬态不单独绘制。

新增 `max_polyphony` 参数范围 1–16，默认以及旧状态缺失值均为 16。预分配声部池仍为 16，音符分配/抢占只在所选范围内进行；调低上限时，多余槽位通过现有短淡出退出并取消其待启动音符。保留槽位的共鸣状态不清空。过程回调包括零样本事件刷新都会应用上限；不改变泛音上限或 Unison 数，也不增加音频回调分配。

`ui_max_fps` 与 `ui_debug_fps` 为持久化字段，默认 60/false，不作为音频自动化参数。`editor_diagnostics.rs` 在 UI 线程记录实际帧间隔、界面构造和分析耗时；每类最多保存 512 项，FPS 浮层使用最近约一秒。只有显式提供 `SPECTRAL_UI_PROFILE` 路径时才在窗口关闭后输出汇总 JSONL。UI 构造耗时不包含后续 GPU 提交；帧间隔则包含整个渲染/等待/宿主调度流程，不能将构造耗时当作总帧时间。

Windows baseview 0.3.4 的原 15 ms SetTimer 不足以支撑 90/120 FPS。新增每窗口高精度 waitable timer 工作线程，只投递合并的唤醒消息（最多一个未处理消息），不在工作线程绘图，也不调用全局 `timeBeginPeriod`。窗口隐藏时延长睡眠，销毁 HWND 前回收线程；失败时保留原定时器后备。egui-baseview 0.7.2 在消费重绘请求前统一检查帧期限，使用绝对小数周期并丢弃错过的期限，避免渲染耗时不断叠加和追赶式突发绘制。

真实 CLAP 窗口测试进一步定位到上游 wgpu 渲染中的条件错误：MSAA 关闭时 `msaa_texture_view` 必然为空，却因此每帧重建 surface，造成 GPU 等待。修正为只有启用 MSAA 时才要求对应纹理，正常帧复用 surface。插件选择 AutoNoVsync，由显式帧率上限调度；平台仍可能回退至受显示刷新限制的模式。瀑布分析继续为 30 行/秒，在两行之间插值纹理游标；音频停止时最多外推一行，Freeze 保持当前位置。

本版渲染/定时补丁各自说明于 `vendor/egui-baseview/PATCHES.md` 和 `vendor/baseview/PATCHES.md`。具体性能分布、GUI 生命周期、音频回归及制品记录见 [0.10.0 验证](validation/UI_CONTROLS_2026-09-27.md)。这些证据不等于音频宿主实际工程的显示流畅度或 Bounce 验收。
