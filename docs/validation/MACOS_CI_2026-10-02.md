# macOS 云端编译与自动测试（2026-10-02）

## 目的与改动范围

在维护者没有 Mac 的情况下，用 GitHub 托管的 macOS runner 验证当前 0.15.0 源码。采用独立分支 `codex/macos-build-test`，不将测试分支自动合并到 `main`，不创建正式 Release。

新增 `.github/workflows/macos.yml`、`scripts/bundle-clap-macos.sh` 和构建文档。`rust-toolchain.toml` 保持 Rust 1.95.0，移除多余的 Windows target 自动安装项，让 rustup 使用当前平台的默认 host target。Windows 构建脚本、DSP 算法、参数、CLAP ID 和界面代码没有修改。

## 打包和证据边界

脚本生成带 Info.plist、Mach-O 可执行文件及基础版权材料的 `.clap` 目录 bundle，验证 CPU 架构、`clap_entry` 导出和 ad-hoc 签名，然后压缩为 ZIP 并生成可在下载目录使用的 SHA-256 校验文件。工作流解压这份 ZIP 后再执行插件接口测试，确保检查的是打包制品。

通过的包与对应提交的源码归档作为 Actions artifact 保存 14 天；失败时也尽可能上传环境及日志。测试包未做 Developer ID 签名或公证，不是正式安装包。GPL 对应源码和现存第三方许可材料的发布边界仍参见 [发布许可审计](RELEASE_LICENSE_AUDIT_2026-09-30.md)。

编译、源码测试、CLAP validator、模拟宿主离线探针和真实宿主验收分别记录。当前没有真实音频宿主加载、交互 GUI、Retina、硬件音频实时负载或真实工程 Bounce 的验收；也没有更早 macOS、AU、VST3 或 Universal 2 的验证。
