# 0.9.0 GPU 编辑器与宿主湿声路由

日期：2026-09-27。这是 Windows 开发版，真实音频宿主的界面操作、辅助输出布局选择与 Bounce 验收仍待确认。未修改用户的音频宿主工程。

## 官方接口调查

- [CLAP GUI](https://github.com/free-audio/clap/blob/main/include/clap/ext/gui.h)定义插件自建窗口嵌入宿主父窗口或浮动窗口。这里采用 Win32 子窗口，由音频宿主提供外层窗口。
- [CLAP mini-curve-display 草案](https://github.com/free-audio/clap/blob/main/include/clap/ext/draft/mini-curve-display.h)确实允许宿主绘制插件的小曲线，并可叠放多个曲线。它传输一维数值曲线，由宿主选择颜色和呈现形式，没有任意纹理 / 画布、时间-频率二维瀑布或鼠标拖动接口。本次没有实现该草案，也未确认当前音频宿主是否支持它。
- 因而采用已经授权的 GPU 编辑器方案。没有把“未找到公开原生组件 SDK”扩张成“音频宿主内部绝无此能力”。

## 实现

依赖：nice-plug 0.4.2、nice-plug-egui 0.5.1、egui 0.36.1、egui-baseview 0.7.2、wgpu 30.0.1、RustFFT 6.4.1。egui 的 MSRV 要求使项目工具链由 1.92 升为已安装的 Rust 1.95。只启用 wgpu 后端，不增加 VST3。锁文件记录实际解析版本。

`src/editor.rs` 使用同一组稳定宿主参数，不维护音频参数的 UI 副本。交叉频率可用线条、旋钮、数值框修改，Shift 拖动细调。参数通过 begin/set/end 手势进入宿主，模式使用下拉框。界面分 Resonance、Decay Curve、Motion / Unison、Routing 四页，支持最小 980×700 逻辑尺寸，默认 1120×780。

瀑布图为 512 列、256 行 GPU 环形纹理，约 30 行/秒，频率轴 20 Hz 至 min(20 kHz, Nyquist)。只更新新行，两个 UV 矩形完成环形滚动。蓝色为原始输入，额外延迟 4096 样本与 STFT 基础延迟对齐；白色来自实际 Post Unison 之后的时间域湿声，包括 Mid Mix、Wet Level、Output Gain。Post 的变调延迟属于效果本身，不额外抹除。亮度约 -84～0 dBFS，超出上界饱和。

`src/analyzer.rs` 在音频侧只保存短数据块：每块 256 帧、四路 f32（dry L/R、wet L/R），有序号、采样率和 reset epoch。32 块有界队列饱和即丢显示数据；音频线程不 FFT、不分配、不获取 UI 锁、不等待 GPU。UI 对丢帧 / reset 加入断点行并清空不连续 FFT 窗口。FFT 4096、Hann 窗，左右按功率平均，反相不会相消。关闭 / 隐藏编辑器或 Freeze view 时停止发送显示数据；音频处理仍继续。

显示 FFT 在 UI 线程，GPU 负责绘制。这里并未把音频 DSP 搬上 GPU，也不声称显示完全零 CPU 开销。当前音频侧仍维护固定大小的输入延迟环。

## 路由

默认 Stereo 与 Mono 保持不变。新增可选第三布局 Stereo + Wet，其辅助立体声端口名为 Wet / Post Unison。Main Output 参数具有 Mixed / Dry contribution / Wet only 三种状态；切换贡献系数平滑过渡约 20 ms。辅助湿声不受 Main Output 选择影响，但受 Output Gain 影响。

在支持布局选择的宿主中，选择 Stereo + Wet，把主输出设为 Dry contribution，并在湿声输出链内放置效果器，再由宿主相加。Mixed 与 Wet 同时相加会重复湿声。若音频宿主不暴露该布局切换，Wet only 主输出也能串接宿主效果器；配合 宿主的并行效果链 的旁路干声链则保留完整干声，与内部经过分频的干声贡献不同。

白色图只分析本插件输出；没有回传通道，因此不会显示音频宿主后续效果器的结果。CLAP Remote Controls 提供 Perform、Motion、Resonance 三页，各八个参数。旧状态缺少 output_mode 时迁移为 Mixed，避免在已有 Wet-only 实例中加载旧预设后误留在湿声路由。

## 框架修补

保留 0.8.2 的 render/tail 修复。额外修复 GUI 初始化缺少宿主 GUI 回调时的 Option unwrap，使 create 返回 false。

nice-plug-egui 上游声明 `editor_closed` 却没有调用；本地补丁在窗口 handler 销毁时转发清理，释放持有的 egui Context，在 show/hide 后更新可见性。数值输入框也限定为当前列剩余宽度。来源和边界见两个 vendor 目录的 PATCHES.md。

## 验证

- 源码测试：DSP 36、插件 27，通过；独立 GPU 测试默认忽略，已另行运行并通过。包含干湿相加还原、辅助输出等于 Post 湿声、声道隔离、显示队列满时零分配、反相信号可见、丢帧重新分析、分频拖动的宿主手势和四页窗口边界检查。
- GPU 离屏图：实际 NVIDIA GeForce RTX 4060 Laptop GPU，Vulkan，驱动 595.97。八秒扫频与噪声经过真实 DSP 后送入同一个生产 UI，输出四页图片，目视修复数值越界和底部裁切。图片为离屏渲染，并非音频宿主截图。
- `cargo fmt`、全目标 / 全功能 Clippy `-D warnings` 通过；release 构建保留上游两个 unused-variable 提示。
- CLAP 验证器：36 passed、0 failed、0 warnings、8 skipped。
- CLAP GUI 测试宿主：独立音频线程，三次 create/parent/show/hide/destroy，窗口从 1120×780 调到 1260×860，再验证最小尺寸钳制。没有声卡输出。测试宿主限制每轮处理的 Windows 消息数，避免连续重绘使自己的截止时间得不到执行。
- 双线程 Bounce：Internal/MIDI × Spectral/Post 四组均通过；共 12 次离线录制，48/44.1/96 kHz。浮点音频哈希与 0.8.2 全部相同，尾音可正常结束。

证据文件位于 `target/ui-tests-final.log`、`target/ui-preview-test.log`、`target/ui-interaction.log`、`target/ui-clippy.log`、`target/ui-validator.log`、`target/ui-host-final.log`、`target/ui-bounce/`。界面图位于 `target/ui-preview/`。

桌面截图请求的应用授权没有完成，因此没有通过桌面自动化验证音频宿主内的点击。分频拖动已在同一 egui 界面和模拟参数宿主中测试；实际音频宿主缩放、自动化录制、GPU 设备丢失恢复、不同显卡 / 多实例压力仍不在本次通过范围内。之前的真实音频宿主 Bounce 挂起也不能仅凭这些模拟结果宣布解决。
