# 0.7.3：8 路 Unison、16 MIDI 声部验证

日期：2026-09-27。用户澄清原本希望将 Unison 扩至 8，并要求测试 16 MIDI 声部。本版已实现两项扩展，保留原有 Voice Spread。源码与 CLAP 检查通过；16 声部本身可工作，但 16×8×256 的实时性能取决于块长，不能因功能测试通过就宣称任何组合都能实时运行。

## 行为与兼容

- Unison 范围 1–8，默认仍为 1，稳定 ID `unison_voices` 不变。八个副本各自拥有连续相位与调制源，共享所属音符的输入投影与衰减状态；按淡入淡出的副本增益总和归一化。
- 固定 MIDI 池从 8 扩至 16，包含释放尾音。第 17 个音符优先抢占最安静的释放尾音，否则抢占最早按下的音符；仍先短淡出再启动替代音符。
- Voice Spread 保留原八位置循环，16 个音符可共享位置。位置取决于音符生命周期顺序，不依赖物理槽位或活动声部数；Unison 副本跟随所属音符。左右音频状态保持独立。
- Harmonics 仍为 1–1024、默认 256。未改变 FFT/Hop（4096/512）、报告延迟、干声路径或电平管理，未静默降低用户参数。
- 保存过的 Unison=1/2/4/8 与 Spread 值经过迁移测试保持原值。缺失的参数沿用既有默认。超过八个重叠音符时，新版会保留更多共鸣，因此这类旧工程的声音和负载可能变化。

53 项测试通过（DSP 31、插件 22），fmt、Clippy、release 构建通过。版本副本和稳定文件分别通过 CLAP 验证：**36 passed、0 failed、0 warnings、8 skipped**。日志在 `target/unison8-artifact-validator.txt`、`target/unison8-stable-validator.txt`。

关键覆盖：

1. 八路 Unison 各自达到目标失谐频率，稳态增益均为 1/8，实际合成频谱与逐路参考累加相符；减为两路时退出副本先淡出。
2. 16 个不同音高、每音 8 路 Unison 的真实渲染等于两组 8 音的独立输出之和，干声只计一次；16 个共鸣状态都非零，松键后仍有自然尾音，左输入不会串入右输出。
3. 满池后的第 17 个音符、最安静尾音抢占、最早按键抢占、全部待启动槽满额、短音符 note-off/choke 和 Panic 均通过。Spread 在释放、复用和抢占后维持旧尾音的位置。
4. 真实 `Plugin::process` 在 **192 kHz、16 声部、1024 泛音、8 路 Unison、Spread=100%** 下填满池后进行密集替换、松键和 reset。16 个初始声部均为 MIDI 33 且身份独立，该采样率允许它们完整包含 1024 泛音。callback/reset 的 alloc、realloc、dealloc 总计均为 0，输出有限且无左右串音。此项检查正确性和内存行为，未对 192 kHz 做实时性能验收。
5. Chorus/Wander/Granular/Off 与 Unison 8→3→8→1→2、衰减曲线和 Spread 自动化，在固定块与可变块下逐样本一致，保留干声路径与尾音。

## 内存

目标平台实测 `size_of::<Lane>()=72`、`size_of::<Voice>()=20592`：

| 预分配状态 | 0.7.2 | 0.7.3 |
| --- | ---: | ---: |
| 泛音调制 lane | 8×1024×4×72 = 2,359,296 B | 16×1024×8×72 = 9,437,184 B |
| Voice 池 | 8×20,592 = 164,736 B | 16×20,592 = 329,472 B |

两项合计增加约 **6.91 MiB/实例**，主要来自调制副本池。模板、FFT、bank 元数据、宿主和分配器开销另计；这不是进程工作集测量。整个池在初始化时分配，实际少用几路会减少计算，但不会缩减该预分配内存。

## 离线性能方法

CPU：AMD Ryzen 9 7945HX。Release 构建，无 profiling 功能、没有在基准期间并发执行编译或验证器。每配置顺序运行三轮，每轮四组场景、每组 8 秒双声道音频；初始化、音频生成与写文件排除在计时之外，事件派发计入。音频前 5 秒有衰减噪声激励，后 3 秒为零输入；因此它是此合成素材下的短时离线负载，不覆盖所有音色、长时间热状态和整个宿主工程。

`render_m4` 新增最后一个位置参数：每组音符数，默认 8，范围 1–16；同时打印固定池容量和各场景实际峰值活动声部数。持续和弦及曲线自动化场景中，16 音用两组 MIDI 33–40（独立身份），与 8 音保持相同低音分布，避免高音的 Nyquist 裁剪掩盖额外成本。16 个不同音高的音频正确性另由源码测试覆盖。

四组场景为持续和弦、每 12,000 samples 换和弦、每 64 samples 一个新音符的密集抢占、持续和弦并连续改变衰减曲线。后两类压力行为不代表普通演奏速度。换和弦与密集事件中，8 个新音符加上旧尾音也会达到 16 活动声部，不能当作固定 8 声部池的负载。

公共设置：48 kHz、Curve、Rate=3 Hz、Amount=70%、Pitch Mod=0.2 st、Detune=12 cents、Spread=0%。除表中 Off 对照外均为 Granular。泛音与副本数不自动降低。试听 WAV 仍为历史两组四音和弦，不应误称为十六声部试听素材。

复现示例：

```powershell
cargo build -p spectral-dsp --example render_m4 --release --locked --offline
./target/release/examples/render_m4.exe target/fixtures/16x8-256 256 48000 granular 8 curve 256 16
./target/release/examples/render_m4.exe target/fixtures/16x8-512 256 48000 granular 8 curve 512 16
```

原始逐轮日志、WAV、汇总 CSV/JSON 在 `target/perf-0.7.3/`。256 samples 共 18 次配置运行、72 组场景，每组 1500 块；512 samples 另有三轮、12 组场景，每组 750 块。未删除异常峰值。下面的 p99 是每组约 99% 的块耗时不超过的数值，不是最大值。

## 48 kHz / 256 samples：8 与 16 声部对照

每块预算 **5.3333 ms**。本表只取持续和弦场景，严格对应 8 或 16 活动声部；均值和 p99 分别取三轮中位数，最大值取三轮全部块中的最大值。

| 活动声部 | 泛音上限 | 模式 / Unison | 均值中位数 ms | p99 中位数 ms | 最大 ms |
| ---: | ---: | --- | ---: | ---: | ---: |
| 8 | 64 | Granular / 8 | 0.3034 | 0.7495 | 1.1731 |
| 16 | 64 | Granular / 8 | 0.5804 | 1.4289 | 1.9013 |
| 8 | 256 | Granular / 8 | 1.0650 | 2.6818 | 4.8496 |
| 16 | 256 | Granular / 8 | 2.1365 | 5.1608 | 5.9795 |
| 16 | 256 | Granular / 4 | 1.2404 | 3.2036 | 5.2929 |
| 16 | 256 | Off / 1 | 0.4111 | 1.0796 | 1.5659 |

在相同泛音、Unison 与低音分布下，持续和弦从 8 增至 16 声部，平均耗时约为 1.91 倍（64 泛音）和 2.01 倍（256 泛音）。FFT 次数保持不变，增加的主要是每声部的泛音状态更新、调制准备和湿声合成；本轮未重复做分段热点归因，不把以前的百分比冒充本版实测。

## 全部压力场景与块长

下表取每配置三轮、四场景中的**最高 p99**，以及这些块中的**绝对最大值**；没有将多个场景的样本重新汇成一个 p99。

| 每组新音符 | 泛音 | 模式 / Unison | 块长 | 最高 p99 ms | 绝对最大 ms | 预算 ms |
| ---: | ---: | --- | ---: | ---: | ---: | ---: |
| 8 | 64 | Granular / 8 | 256 | 1.7942 | 2.5788 | 5.3333 |
| 16 | 64 | Granular / 8 | 256 | 2.4981 | 3.6464 | 5.3333 |
| 8 | 256 | Granular / 8 | 256 | 8.0908 | 24.3585 | 5.3333 |
| 16 | 256 | Granular / 8 | 256 | 7.3043 | 40.3222 | 5.3333 |
| 16 | 256 | Granular / 4 | 256 | 3.8912 | 5.2929 | 5.3333 |
| 16 | 256 | Off / 1 | 256 | 1.3220 | 2.1854 | 5.3333 |
| 16 | 256 | Granular / 8 | 512 | 6.5245 | 8.5779 | 10.6667 |

8 音组的换和弦和抢占场景同样达到 16 声部，其结果受尾音、等待替换与新声部启动时间影响，不能用它与 16 音组压力结果直接判断声部数缩放。40.3222 ms 的峰值出现在首轮 16×8×256 换和弦场景；24.3585 ms 出现在第二轮 8 音组换和弦场景。这里记录的是普通离线进程的墙钟时间，包含调度波动，没有证据将单个峰值全部归因于 DSP 算法，也没有删掉它们。

结论是：16 MIDI 声部可用，64 泛音配 8 Unison 在本次 256 samples 测量中有余量；256 泛音配 4 Unison 虽未超出预算，但绝对峰值已接近上限，不能承诺复杂宿主工程仍有同样余量。16×8×256 在 256 samples 下出现多组 p99 超预算，不宜宣称稳定实时。512 samples 将每块可用时间增至 10.67 ms，本次相同重负载三轮最大 8.58 ms，可作为音频宿主试听该组合的起点。这些结果没有改变用户此前反馈的 0.7.0 在音频宿主当前工程运行正常这一事实。
