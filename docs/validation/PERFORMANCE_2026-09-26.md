# 0.7.1：频谱合成热点与性能优化

日期：2026-09-26。用户反馈 0.7.0 在音频宿主当前工程运行正常，截图显示 48 kHz、256 样本块、Deadline=5.333 ms、平均 0.903 ms、最大 1.719 ms。该截图是宿主当前工程的观察结果；此前 128 样本块的离线压力测试超预算不能解释为已经观察到用户宿主断音。本次按用户要求定位热点并实施一轮保持声音模型的优化，没有提交 Git。

## 分段定位

新增 `profile_hotspots` 示例与显式 `profiling` feature，统计六段累计处理时间。普通 CLAP 构建不启用 feature，不带计时调用。测量配置：本机 AMD Ryzen 9 7945HX、Windows x86-64、release、48 kHz、立体声、N=4096/H=512、8 个低音（MIDI 33–40）、256 泛音；4 秒持续随机输入；Granular、Unison=4、Rate=3 Hz、Amount=70%、Pitch Mod=0.2 半音、Detune=12 音分，六点曲线均为 2 秒。

| 段 | 优化前累计 ms / 占比 | 优化后累计 ms / 占比 |
| --- | ---: | ---: |
| 控制与衰减系数 | 0.487 / <0.1% | 0.228 / <0.1% |
| 调制轨迹准备 | 157.680 / 14.9% | 151.884 / 30.6% |
| 输入整理与 FFT | 8.865 / 0.8% | 7.801 / 1.6% |
| 输入投影与共鸣状态更新 | 160.893 / 15.2% | 99.045 / 20.0% |
| 湿声频谱合成（新版含统一镜像） | 714.462 / 67.4% | 221.407 / 44.6% |
| 混合、IFFT 与 overlap-add | 17.860 / 1.7% | 15.733 / 3.2% |

整段墙钟时间约 1063.499 → 499.487 ms。表中是 hop 内粗粒度测量，不包含所有逐样本调度；探针、缓存与 CPU 频率会影响绝对数值，不能据一轮表格把各段变化全部归因于代码改动。性能收益另用下面三轮无探针 A/B 确认。最明确的热点是逐泛音频谱合成；FFT 并不是当前主导项。

关闭调制、Unison=1 时，原来的输入投影/状态更新约占 43%，合成约占 46%，两者接近。持续修改衰减曲线时，旧版系数更新约占 4.6%；因此不能把曲线求值视为本轮的首要瓶颈。

## 实施的优化

原实现每个声部、每个泛音、每路 Unison、每个声道都向 65 个核点写入正频率值，再向 65 个镜像位置写入共轭值。8×256×4×2×65×2 约为每 hop **213 万次复数累加写入**（实际数量仍受频率边界和状态是否为零影响）。

新版先累加全部正频率瓣，再每声道一次生成完整共轭频谱：`X[k] = P[k] + conj(P[-k])`。同时将动态核的常见路径改为连续切片，减少内循环中的索引计算和分散写入。镜像工作由每个泛音重复执行变成一次 O(N) 遍历；没有新增频谱缓冲。

保持全部 65 个核点、复数插值精度、原始相位轨迹、1024 上限/256 默认、8 声部、1–4 路 Unison、L/R 独立、参数及状态格式、4096 样本延迟。跨 DC 的核仍完整循环包裹；最终镜像按成对读取旧值再写回处理，DC/Nyquist 单独处理，交叠频瓣不会丢失。浮点求和顺序改变，输出不要求逐 bit 相等。

## 三轮无探针 A/B

保留优化前已构建的 0.7.0 `render_m4.exe`，与正常 release 的新版示例顺序运行，没有并行跑负载。顺序为旧→新、新→旧、旧→新。每场景 8 秒、48 kHz、128 样本块、3000 块，测试包含事件分派和 DSP，排除初始化、文件写入和 nice-plug 参数适配。所有组为 8 声部、256 泛音、Curve；其余参数与 0.7.0 的 `render_m4` 一致。

## 复现与后续优先级

```powershell
$env:CARGO_HOME = Join-Path (Get-Location) 'target/cargo-home'
$env:RUSTUP_TOOLCHAIN = '1.92.0'
# 分段定位；带探针，不用其绝对耗时冒充正常插件耗时。
cargo run -p spectral-dsp --example profile_hotspots --features profiling --release --locked --offline
# 正常无探针测量，最后一个参数是块长。
cargo run -p spectral-dsp --example render_m4 --release --locked --offline -- target/fixtures/perf-granular 256 48000 granular 4 curve 256
# 比较 render_m4 生成的两份 float stereo WAV；需要可用的 Python 3。
python scripts/compare-audio-fixtures.py path/to/old.wav path/to/new.wav
```

本轮之后 Granular×4 的合成仍约占 45%、调制轨迹约 31%、投影/状态约 20%。进一步优化应优先评估这三段，结合缓存、数学函数和可向量化的内循环；单纯更换 FFT 或引入 GPU 不是当前证据支持的优先方向。不能用无依据地减少核点、静默降低泛音数、截断尾音或合并左右声道换取性能。0.7.1 的音频宿主实际听感、长时间调度、多实例和工程保存恢复仍待宿主复验。
