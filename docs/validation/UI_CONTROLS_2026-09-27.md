# 0.10.0 UI 组织、衰减图与帧率验证

日期：2026-09-27。按控件、页面/曲线、帧率后端三个阶段实现，最后验证同一个 Windows x86-64 CLAP 制品。构建使用 Rust 1.95.0、锁定离线依赖。未自动提交本轮改动。

## 用户可见行为

- 所有数值控件采用左旋钮、右上名称、右下数值/单位，不附带横向滑条。数值显示最多五位有效数字；文本输入不按显示位数舍入，保留 f32 参数精度。点击数值输入，Enter/失焦提交，Escape 取消，Shift 拖动细调，旋钮双击恢复默认。整数旋钮会积累小于一档的拖动量。
- Wet Level / Output Gain 显示和拖动使用 dB。Wet Level 原默认 4 倍显示为 +12.041 dB，范围最高 +24.082 dB；Output Gain 原默认 1 倍为 0 dB，最高 +6.0206 dB。最低端静音，文本支持 `-inf dB`。参数 ID、线性保存值与自动化范围保持兼容；Excitation 已是 dB，不重复换算。
- 顶部 Settings 选择最大 UI 帧率 30/60/90/120，默认 60；可在频谱右上角显示实测 UI FPS。设置为持久化字段，随工程/预设保存。
- 分频线静止时暗淡，名称/Hz 框只在 hover 或拖动时出现；框按文字宽度计算并限制在频谱内。鼠标移到其他频谱位置显示相应 Hz。窗口增加的高度继续分配给频谱。
- MIDI 模式隐藏 Root Note 并显示 Maximum Polyphony（1–16，默认 16）。Mute wet / panic 为保持式按钮。调低复音上限时，多余声部按原短淡出退出，不清空保留声部。
- Decay Curve 集中 Decay model、T60 和阻尼。Damping 图横轴为泛音阶数/基频倍数，Curve 图横轴为绝对 Hz；不能在多音符情况下将相对阻尼误画为唯一的 Hz 曲线。两者调用与 DSP 相同的函数。
- Curve 的六个节点可拖动，也可选择节点后用 Hz/T60 旋钮及文本精调。各节点允许交叉，沿用原排序/重复频率规则。Damping、Curve、Internal、MIDI 切换仅改变显示，隐藏参数不重置。

## 帧率瓶颈和修复

旧插件主动等待约 33 ms，Windows baseview 的 SetTimer 又以约 15 ms 轮询。因此增加帧率选项需要改动后端调度。新版使用每窗口高精度 waitable timer，仅向宿主 UI 线程发送合并唤醒消息，渲染仍在宿主窗口线程。没有全局 `timeBeginPeriod` 或音频线程等待。egui-baseview 使用统一的绝对帧期限，输入事件和自动化不会绕过上限。

真实窗口初测显示，即使解除上述限制，60/90/120 档仍只有 32.761/33.391/33.554 FPS。CPU 界面构造均约 0.45–0.46 ms，不能解释约 30 ms 的帧间隔。进一步检查发现上游 wgpu renderer 将 `msaa_texture_view.is_none()` 当作无条件重建 surface 的理由，而 MSAA 关闭时该纹理本来就不存在。修复后只在大小变化或启用 MSAA 且缺少纹理时重建，消除每帧 swapchain 重建/GPU 等待。

瀑布图仍分析 30 行/秒，历史仍约 4.27 秒，UI 以所选帧率插值滚动位置。调高 FPS 不增加音频 DSP 或显示 FFT 的频率。显示采集继续使用有界队列，音频回调不分配、不锁 UI、不访问 GPU。

## 实际窗口测量

测试使用 `scripts/probe-clap-editor.py` 创建真实 Win32 父窗口，加载 release CLAP 的 GPU 编辑器，同时在独立音频线程运行 48 kHz / 256 样本块，Internal/Chorus/Post Unison×4，扫频与噪声激励。音频只写内存。窗口 1120×780，每档观察 8 秒，各档顺序单独运行，期间无并行编译或音频压力测试。

诊断记录最多保存最后 512 个帧间隔，因此 90/120 档分别覆盖末尾约 5.69/4.27 秒。UI FPS 是实际进入 UI 的帧率，不是显示器扫描率；后端成功提交画面的表现也仍受显示环境影响。`ui_mean_ms` 包含 `analysis_mean_ms`，两者不能相加；UI 时间不包含后续 GPU 提交等待，帧间隔包含完整的调度周期。

最终制品结果：

| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 30 | 29.997 | 238 | 33.312 | 34.469 | 35.304 | 0.438 | 0.261 |
| 60 | 59.865 | 475 | 16.675 | 17.760 | 33.830 | 0.284 | 0.124 |
| 90 | 89.987 | 512 | 11.026 | 12.251 | 12.821 | 0.248 | 0.091 |

surface 修复后的上一轮四档结果为 29.996/59.990/90.017/120.003 FPS；最后一轮是在补齐整数旋钮慢拖动后重测。说明四档可接近目标，但 60 档仍观察到一次约 34 ms 长帧，不能宣称完全无抖动或任意 Bitwig 工程恒定满帧。

原始记录：`target/ui-0.10.0/fps-*.jsonl`（surface 修复前）、`fixed-fps-*.jsonl`（修复后首轮）、`final-fps-*.jsonl`（最终制品）；各自的 `*-gui-*.log` 记录生命周期和音频持续运行。正常运行不输出诊断文件；只在显式设置 `SPECTRAL_UI_PROFILE` 时关闭窗口后写入汇总。

- 源码：DSP 37、插件 36，总计 **73 passed**，另有 GPU 测试默认忽略。覆盖高精度输入、五位显示、dB 换算、慢速整数旋钮、隐藏值保留、曲线拖动手势、设置持久化、旧状态迁移，以及回调内改变复音数时的零分配和左右隔离。源码测试日志 `target/ui-0.10.0/source-tests.log`。
- `cargo fmt` 和全目标/全功能 Clippy `-D warnings` 通过。release 构建仍保留原 vendor/nice-plug 中两个 unused-variable 提示，与本轮改动无关。
- 真实 GPU 离屏预览另行通过：NVIDIA GeForce RTX 4060 Laptop GPU / Vulkan / 595.97。使用生产 UI 和 DSP 扫频/噪声生成四页、加高窗口、Curve、Settings 图，位于 `target/ui-preview/`。已检查图表布局和文本单位；这是自有测试渲染，不是 Bitwig 截图，预览浮层数字也不是窗口性能基准。
- 布局测试覆盖四页的 980×700、1120×780、1120×1100，验证增加 320 像素高度时频谱也增加 320 像素。设置浮窗完成首帧测量和淡入后再截图。
- 最终 CLAP validator：**36 passed、0 failed、0 warnings、8 skipped**，`target/ui-0.10.0/validator.log`。
- 最终 CLAP GUI 生命周期：120 FPS 档，1120×780 → 1260×860 → 980×700，三次创建、显示、隐藏、关闭重开通过；独立音频线程完成 2497 块。缺少宿主 GUI 回调时正常拒绝创建。`target/ui-0.10.0/lifecycle.log`。
- 最终模拟 Bounce：Internal/MIDI × Spectral/Post × 48/44.1/96 kHz，共 **12 次通过**，有限尾音可结束。12 份原始音频哈希与已有 `target/ui-bounce/` 的上一 UI 基线逐份相同；`target/ui-0.10.0/bounce/comparison.json` 保存对比。默认最大复音仍为 16；这组音频回归不覆盖所有新上限值，后者由 DSP/回调测试覆盖。

真实 Bitwig 的窗口流畅度、工程负载、显示缩放和 Bounce 验收仍待用户环境确认。所有测试保留真实 4096 样本延迟；没有用零延迟或实时导出来规避宿主问题。
