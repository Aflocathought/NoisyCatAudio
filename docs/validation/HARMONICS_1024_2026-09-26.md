# 0.6.1：泛音上限 1024，默认 256

日期：2026-09-26。在 0.6.0 的 8 声部复音基础上，按用户要求扩大 Harmonics 范围。保留 Mid Mix、自然尾音、左右独立状态及 4096 样本报告延迟。本次未提交 Git。

## 参数、内存与兼容性

宿主参数 `Harmonics` 的稳定 ID 仍为 `harmonics`，整数范围从 1–64 扩至 **1–1024**，新实例默认由 32 改为 **256**。DSP 的默认值、模板上限、声部状态容量及衰减系数容量同步更新，共用常量以避免界面和声音引擎范围不一致。

已有预设中保存的 1、32、64 等数量保持原值，新版本保存的 256、1024 也原样恢复。缺失 Harmonics 的历史预设继续补为旧值 32，保留旧音色；这与新实例默认 256 是不同的兼容规则。参数 ID 和状态格式没有更换。

8 声部 × 左右双声道 × 1024 个 f32 复数，共鸣状态占 **128 KiB**，不包含 FFT 缓冲、模板及元数据。整个固定声部池改为激活时分配的 `Box<[Voice]>`，避免引擎创建、移动时携带庞大的栈内数组；note-on、抢占、Panic 和 reset 均复用已有存储。模板仍在激活时建立，音频线程不动态创建泛音或 FFT plan。

合成内环利用固定二次幂 FFT 长度，用位掩码计算共轭镜像频点，去掉逐模板点的整数除法。FFT 长度校验保证这个替换成立，原直接合成参考与频谱误差测试继续通过。

## 有效数量与频率上限

Harmonics 是请求上限。沿用 `h × f0 < 0.49 × fs` 的安全边界，并在接近边界时渐弱，超出范围的泛音不生成模板，避免混叠。55 Hz 基音（MIDI 33）可用上限如下：

| 采样率 | 有效泛音上限 |
| --- | ---: |
| 44.1 kHz | 392 |
| 48 kHz | 427 |
| 96 kHz | 855 |
| 192 kHz | 1024 |

更高基音可用泛音更少。即使在安全边界以内，High Damping 和中频分频仍会衰减高次泛音，因此设置 1024 不代表可以听到 1024 个等响度成分。没有扩大原 MIDI 33–93 的基音范围，也没有改变分频点范围。

## 验证

工具链为 Rust/Cargo 1.92.0，nice-plug 0.4.2，RustFFT 6.4.1，clap-validator 0.4.1；未新增依赖。

- `cargo fmt --all -- --check`、`cargo clippy --workspace --all-targets --locked --offline -- -D warnings`、release 构建通过。
- `cargo test --workspace --locked --offline`：**39 项全部通过**，其中 DSP 20 项、插件 19 项。
- 新增模板检查覆盖 44.1/48/96/192 kHz、低中高音，确认高次泛音突破旧 64 上限且不越过 Nyquist 安全边界。
- 实际激励第 128、256、1024 个泛音，分别在 48/96/192 kHz 检查状态能量；调低数量到 64 后，原高次状态继续按其相位和短衰减系数演化，而非突然清零。右声道无输入时保持零，输出均为有限值。
- 实际 `Plugin::process` 在 **192 kHz、8 声部、1024 泛音** 下经过密集抢占及 note-off，堆分配、重分配和释放计数均为 **0**；随后 reset 同样为 **0**，无残留活动声部。
- 新实例默认 256、宿主上限 1024、旧预设缺省 32，以及保存值 1/32/64/256/1024 保持不变的检查通过。
- 既有复音、自然尾音、踏板、Panic、Mid Mix、立体声、音准、T60 和跨块一致性测试继续通过。
- 版本副本及更新后的稳定路径各通过 CLAP 验证：**36 通过、0 失败、0 警告、8 跳过**。

## 离线负载结果与限制

本机 AMD Ryzen 9 7945HX，Windows x86-64，release、立体声、N=4096、H=512、128 样本块、T60=2 秒，最多 8 个声部。每组处理 8 秒合成输入；48 kHz 为 3000 块，192 kHz 为 12000 块。计时包含事件分派与 DSP，排除初始化和文件写入。下表是内环优化后的结果，单位均为 µs：

| 采样率 / 请求泛音 | 场景 | mean | p50 | p99 | max | 每块时间预算 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 48 kHz / 256 | 8 个低音持续按住 | 137.251 | 1.100 | 715.600 | 1147.900 | 2666.667 |
| 48 kHz / 256 | 每 12000 样本替换和弦 | 115.512 | 1.300 | 639.900 | 1031.100 | 2666.667 |
| 48 kHz / 256 | 每 64 样本触发新音 | 119.126 | 1.400 | 694.700 | 1014.900 | 2666.667 |
| 48 kHz / 1024 | 8 个低音持续按住 | 175.511 | 1.300 | 909.400 | 1233.500 | 2666.667 |
| 48 kHz / 1024 | 每 12000 样本替换和弦 | 136.860 | 1.100 | 819.400 | 1517.500 | 2666.667 |
| 48 kHz / 1024 | 每 64 样本触发新音 | 143.625 | 1.400 | 809.700 | 1092.400 | 2666.667 |
| 192 kHz / 1024 | 8 个低音持续按住 | 509.522 | 1.400 | 3070.600 | 4804.500 | 666.667 |
| 192 kHz / 1024 | 每 12000 样本替换和弦 | 436.857 | 1.900 | 3371.900 | 4676.000 | 666.667 |
| 192 kHz / 1024 | 每 64 样本触发新音 | 489.803 | 1.900 | 3192.800 | 4767.400 | 666.667 |

48 kHz 的有效数量受到频率边界裁剪，本次默认及最大设置都低于块时间预算；192 kHz 的持续低音场景能启用完整 **8×1024** 个泛音，p99 明显超过预算，**不能把这个极限组合称为可稳定实时运行**。FFT/合成集中在每四个小块中的一个，平均值或 p50 很低不代表没有超时。高采样率下需要降低泛音数或实际同时发声数；未自动缩减用户设置，也未通过丢音来降低计时。

初始化分别约 28.318 ms（48 kHz/256）、27.629 ms（48 kHz/1024）、101.764 ms（192 kHz/1024）；同一采样率总是预计算全部安全模板，故初始化不随当前 Harmonics 参数缩减。耗时来自短时离线引擎，尚无 Bitwig 实时调度、声卡、10 分钟连续运行及多实例验收证据。

复现命令：

```powershell
$env:CARGO_HOME = Join-Path (Get-Location) 'target/cargo-home'
$env:RUSTUP_TOOLCHAIN = '1.92.0'
cargo run -p spectral-dsp --example render_m4 --release --locked --offline -- target/fixtures/harmonics-256-48k 256 48000
cargo run -p spectral-dsp --example render_m4 --release --locked --offline -- target/fixtures/harmonics-1024-48k 1024 48000
cargo run -p spectral-dsp --example render_m4 --release --locked --offline -- target/fixtures/harmonics-1024-192k 1024 192000
```

每个目录同时生成立体声输入和共鸣输出 WAV。这些听感素材采用两组四音和弦，区别于最大负载的低音测试；48 kHz 文件峰值 0.577116，192 kHz 文件峰值 0.537529，均未额外降低试听增益。尚未进行主观试听验收。
