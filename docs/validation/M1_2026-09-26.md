## 已运行的检查

- `cargo fmt --all -- --check`、`cargo clippy --workspace --locked -- -D warnings`、`cargo test --workspace --locked` 与 release 构建通过。
- 流式源码测试覆盖 2048/256、4096/512、8192/1024；混合块长 1、7、64、127、128、257、512、1024 与固定 128 的结果一致。左右反相及不同尾部输入各自重建，单声道脉冲在 N 样本后输出，`reset` 清空待输出内容。测试设定的峰值误差门槛为 3e-5、RMS 误差门槛为 3e-6；两项测试均通过，未单独保存最大误差数值。
- Windows release DLL 被打包为单个 `target/bundled/my_spectral_resonator.clap` 文件。对该文件执行 `clap-validator validate target/bundled/my_spectral_resonator.clap --only-failed`：44 项中 33 通过、0 失败、0 警告、11 不适用而跳过。验证器覆盖基础音频处理、变化块长与采样率、重置/重新激活、参数和状态等 CLAP 行为；它不测量透明音频误差或音频宿主实际延迟。

`cargo +1.95.0 install --git https://github.com/free-audio/clap-validator.git --locked` 在本机因全局 USTC Cargo 镜像返回 404 而未完成。验证器从该 Git checkout 用隔离 Cargo home 编译，二进制放在 `target/tools/bin/clap-validator.exe`。先前目录式 `.clap` 路径不能作为 Windows 动态库交给验证器；改为单文件打包后，上述验证命令通过。

## 宿主证据与待验收项

用户此前确认 M0 增益版本在音频宿主中可以加载，Output Gain 能调节音量，暂未见问题。该反馈不覆盖新的 M1 插件。M1 仍需在音频宿主中验证仅左、仅右与反相信号、脉冲延迟、暂停与 seek、工程保存恢复、多实例以及实际 CPU 消耗。音频宿主版本、采样率、缓冲大小和路由尚未记录。
