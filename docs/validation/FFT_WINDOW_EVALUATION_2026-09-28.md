# 2048 / 1024 点窗口评估

日期：2026-09-28。以当前 0.12.0 源码的 `SpectralResonator` 为对象，只改变诊断实例的 FFT size / hop size；插件仍使用 4096 / 512，未替换发布文件，也未修改 Attack 行为。

## 结论

**建议优先试听 2048 / 512，保留 4096 / 512；1024 可以作为低延迟音色选项，但不宜直接取代当前默认。** 2048 / 512 将基础延迟和短脉冲的时间展宽约减半，测得音准、T60 基本保持，重负载平均耗时与当前接近。代价是频率选择性下降，以及低频自由尾音残差增加。1024 的这些变化更明显；1024 / 512 虽然省时，但只有两倍重叠，尾音杂质增加，不建议作为首选。

这里的“频率范围保留”是指频率覆盖，不代表每个频率的响应和音色完全相同。尚未在音频宿主中验证小窗口版本，也没有做主观盲听；离线测量支持做候选版本，不能代替音乐素材和宿主验收。

## 原理与现有实现

| FFT 点数 | 48 kHz 下基础延迟 | FFT 频点间距 | 一个窗口包含的 150 Hz 周期数 |
| --- | ---: | ---: | ---: |
| 4096 | 85.33 ms | 11.72 Hz | 12.8 |
| 2048 | 42.67 ms | 23.44 Hz | 6.4 |
| 1024 | 21.33 ms | 46.88 Hz | 3.2 |

采样率决定奈奎斯特上限，窗口大小决定频点间距和观察时间。因此三个配置在 48 kHz 下都覆盖到理论 24 kHz；当前泛音实现还会在 21.6–23.52 kHz 逐渐淡出，生成频率低于 23.52 kHz 的泛音，这项规则不随窗口变化。

`partial.rs` 使用小数频率 Hann 投影、相位旋转和合成，并非把 MIDI 频率直接取整到 FFT 格点。因此 1024 的 46.88 Hz 间距**不意味着共鸣音高必须以 46.88 Hz 为步长**。长衰减反馈还能进一步增强频率选择性。但短窗口观察的周期更少，附近输入频率更容易一起激励同一个泛音，快速激励和短 Decay 时尤其明显。

150 Hz 基音的相邻泛音间隔是 150 Hz，而它与高一个半音的基音仅差约 8.92 Hz；“区分泛音”和“区分相邻音符”是不同的要求。当前 Root Note 实际范围为 MIDI 33–93，即 55–1760 Hz，并没有把最低基音限制到 150 Hz。

上表是基础 STFT/宿主延迟，不是所有湿声特征的到达时间。插件默认 `Wet Alignment=0.5` 还会给湿声增加半窗延迟：分别为 42.67 / 21.33 / 10.67 ms。Post Unison 也有自己的可变延迟。本评估质量测量将 Alignment 设为 0，以免把人为延后混入窗口差异。96 kHz 下同样点数的时间减半、频点间距加倍；本报告没有测其他采样率。

## 离线质量测量

全部在 48 kHz，单声道质量测量，Motion Off、单路 Spectral Unison、Wet Level 1、Mix 100%、分频 1/12000 Hz、无 damping，关闭 Reshape。`fast` 是 Independent Attack 0 ms；`natural` 是 Natural、T60 2 s；`short` 是 Natural、T60 5 ms。

### 音准、衰减和自由尾音

分别激励 55、146.832、155.563、220、440、1760 Hz，单个泛音，输入正弦持续 1 s 后停止输入并松开音符。跳过 2N + 100 ms 的刷新时间后测自由尾音。音高用插值过零点测量；T60 用相隔 500 ms 的两个 200 ms RMS 段估计。

尾音残差先撤销目标 2 s 的指数包络，再拟合目标频率的正弦和余弦，报告剩余 RMS 相对原信号的 dB；它包含帧间起伏、镜像、音高/衰减偏差等，**不是标准 THD 或主观可闻性判定**。使用 250 ms 的自由尾音。

| N / H | 最大音高误差绝对值 / cent | 最大 T60 误差绝对值 | 55 Hz 尾音残差 | ≥146.8 Hz 测试音中的最大残差 |
| --- | ---: | ---: | ---: | ---: |
| 4096 / 512 | 0.00027 | 0.263% | −70.91 dB | −77.35 dB |
| 2048 / 256 | 0.00278 | 0.154% | −54.51 dB | −72.70 dB |
| 1024 / 128 | 0.04546 | 0.201% | −37.41 dB | −64.56 dB |
| 2048 / 512 | 0.00484 | 0.155% | −45.59 dB | −64.34 dB |
| 1024 / 256 | 0.05040 | 0.196% | −30.79 dB | −49.72 dB |
| 1024 / 512 | 0.06801 | 0.200% | −21.94 dB | −46.46 dB |

缩窗没有造成这六个测试音明显失准或衰减失控，但只看音准会漏掉低频波形的变化。提高重叠次数能减少部分残差，代价是更多运算。

### 相邻输入频率的选择性

只开启 146.832 Hz 的一个泛音，比较同频输入和高一个半音的 155.563 Hz 输入，持续 2 s，取最后 500 ms RMS。下表为偏频输入输出相对同频输入输出的幅度，越负表示拒绝越强。

| N / H | Natural，2 s | Independent 0 ms，2 s | Natural，5 ms |
| --- | ---: | ---: | ---: |
| 4096 / 512 | −30.34 dB | −6.76 dB | −6.45 dB |
| 2048 / 256 | −25.55 dB | −1.65 dB | −1.57 dB |
| 1024 / 128 | −24.40 dB | −0.57 dB | −0.39 dB |
| 2048 / 512 | −25.46 dB | −1.83 dB | −1.57 dB |
| 1024 / 256 | −24.38 dB | −0.59 dB | −0.39 dB |
| 1024 / 512 | −24.27 dB | −0.50 dB | −0.38 dB |

这解释了为何 1024 仍能输出正确的共鸣音高，却可能更容易被邻近低频激发，听感更宽、更容易混在一起。它不是把输入音直接变成错误音高。Natural 长尾仍有反馈选择性；短尾和快速激励对窗口变化更敏感。

另测了 55 Hz 与 440 Hz 的同频、半音及倍频激励。55 Hz 半音拒绝本来就弱：当前 Natural 长尾为 −16.43 dB，2048 / 512 为 −15.77 dB，1024 / 256 为 −15.55 dB；快速/短尾在三个窗口下都不足 1 dB。完整数据见生成的 `selectivity.csv` / `summary.json`。

### 单位脉冲与音头展宽

440 Hz、8 泛音、三个不同 hop 相位（0、H/2、H−1），其余设置如上。下表只使用 T60 5 ms 的结果，以便将窗口展宽与长共鸣尾音区分开。90% 能量宽度指累积能量 5%–95% 的时间距离。

| N / H | 90% 能量宽度，三个相位均值 | 相对延迟后干声的 −60 dB 起声范围 |
| --- | ---: | ---: |
| 4096 / 512 | 54.42 ms | −70.52 至 −70.48 ms |
| 2048 / 256 | 27.21 ms | −34.19 ms |
| 1024 / 128 | 13.63 ms | −16.04 ms |
| 2048 / 512 | 27.21 ms | −34.21 至 −29.69 ms |
| 1024 / 256 | 13.63 ms | −16.94 至 −14.96 ms |
| 1024 / 512 | 12.18 ms | −15.25 至 −10.13 ms |

这些短尾配置的绝对采样主峰都与延迟后的干声脉冲重合。缩窗明显收窄音头，但不能完全消除相对干声的前响；负时间相对于已经延迟 N 个样本的干声，不是相对于原始输入，也不代表非因果处理。−60 dB 是测量阈值，不是可闻阈值。Natural 2 s / Fast 2 s 也有原始数据，但只记录干声后 500 ms，不能据其能量宽度判断完整的 2 s 尾音。

## 性能

Release、双声道、MIDI 50–65 的 16 复音、最大 256 泛音、T60 0.4 s、Independent Attack 0、Granular、8 路 Unison。基准保留 DSP 默认的分频 250/4000 Hz、HF damping 0.25、Wet Level 4、Alignment 0。轻负载是 MIDI 50 单声部、单路 Unison、Motion Off。各配置串行运行，预热 250 ms 后处理 500 ms 音频，128 样本一块，三次试验轮换顺序取中位数。

| N / H | 单声部用时 | 16 复音 × 8 Spectral 用时 | 16 复音 × 8 Post 用时 |
| --- | ---: | ---: | ---: |
| 4096 / 512 | 7.79 ms | 120.72 ms | 42.90 ms |
| 2048 / 256 | 8.55 ms | 235.71 ms | 78.74 ms |
| 1024 / 128 | 13.80 ms | 473.23 ms | 124.09 ms |
| 2048 / 512 | 5.69 ms | 122.20 ms | 47.07 ms |
| 1024 / 256 | 8.06 ms | 238.33 ms | 71.17 ms |
| 1024 / 512 | 3.52 ms | 125.83 ms | 39.52 ms |

保持八倍重叠会使更新间隔 H 跟着 N 缩小。当前每个泛音的投影/合成都用固定 65 个 tap，更新频率翻倍，泛音、Unison 和调制工作也近似翻倍；FFT 本身变小节约不了这部分。保持 H=512，能维持重负载平均耗时，但小窗口的重叠更少，质量会变化。

以上为本机离线 wall time，不是音频宿主 CPU 表，也不是实时稳定保证。128 样本期限约 2.667 ms，而当前 4096 / 512 重 Spectral 场景的 p99 块用时中位数已有 3.39 ms，2048 / 512 为 3.66 ms；平均用时有余量仍可能遇到单块尖峰。只采样三次、每次半秒，Post 的约 10% 差异不宜当作稳定性能规律。

## 候选档位及后续集成

- 4096 / 512：保留当前声音和较强频率选择性，适合长尾、低音和更密集的频率素材。
- 2048 / 512：优先候选，基础延迟 42.67 ms，短音头时间展宽减半，重负载平均耗时接近当前。2048 / 256 可作为更多重叠的比较项，但本次重 Spectral 用时约为当前 1.95 倍。
- 1024 / 256：可供低延迟、短打击音色试听，基础延迟 21.33 ms；低频残差与相邻频率激励变化更明显，重 Spectral 用时约为当前 1.97 倍。1024 / 128 更耗时，1024 / 512 的质量代价更大。

实际做档位时，需要同步处理插件初始化、真实宿主延迟声明、Wet Alignment 的窗长换算，以及分析器中写死的 `AUDIO_DELAY=4096`。频谱显示可继续使用自己的长分析窗口，避免为了降低音频延迟而损失低频显示精度。不能在音频回调临时创建 FFT plan 或分配缓冲。切换档位宜通过停播/重新激活使宿主正确更新延迟，并针对音频宿主重新做 Bounce 回归。

本次未覆盖 Reshape 与小窗口的联合效果、所有高频泛音、复杂和弦的主观音色、快速参数自动化和其他采样率。用户本次明确暂缓 Attack 后续音符的行为，该逻辑保持原样。
